# 部署与运维

> 合并自原 `docs/05`（Ops 部署运维）、`docs/33`（治理管理接口）、`docs/34`（UI 界面说明）。本文是部署、运维接口与界面的**唯一权威出处**。

## 1. 构建与分发

- 仓库**没有根聚合 pom**，各模块独立：`mvn -f towndemontower-core/pom.xml ...`。
- 编译基线两档：core / gateway = Java 8（class 52，JRE 8 实测可跑）；starter / delivery / agents = Java 17（class 61）。core 必须显式 `--release 8`。
- 对外发布一律 `mvn clean package`，**clean 不能省**：增量编译会把旧 JDK 编出的高版本字节码留在 `target/classes`，随 `lib/` 分发出去。验收办法：读 jar 内任一 class 主版本号，core/gateway 必须是 52，Spring 三模块必须是 61。
- 网关产物是 thin jar + `target/lib/`，两者要一起拷走；Dockerfile 按该结构改写（本机无 docker 守护进程，镜像未实测）。

## 2. 治理管理接口（原 docs/33）

- 前缀 `/towndemontower/admin`，**默认关闭**（`towndemontower.admin-api-enabled=true` 才装配）。
- 鉴权复用 `metrics-token`，走 `X-Governance-Token` 定长比较；未配令牌 403、错误令牌 401。
- 统一响应 `{code, message, data, error}`，前端按 `error` 分支，不按 `message` 文本匹配。
- 能力：审批单 / 执行计划 / 审计 / 同步暂存区的看单、批单、驳单、补传、清理。
- **关键边界**：只提供看单/批单/驳单，**不提供建单口子**——建议单只能由分析链生成。模式切换、权限授予、放行 R3 刻意不开放。

## 3. UI 界面（原 docs/34，已实现）

- 单文件 HTML（内联 CSS/JS、零第三方依赖、不引 CDN、断网可用），路径重定向不变。
- 一个页面两页签：交付看板 + 治理管理（治理含 5 子页签）。数据只来自 `/api/delivery/**` 与 `/towndemontower/admin/**`。
- 令牌仅存 `sessionStorage`；不可操作区不发请求。指标体检开关（`metrics-endpoint`）与 `admin-api-enabled` 是两个独立开关。
- 花名册页面只读——状态流转、审批、计划等写操作走 REST + 治理链，不在页面上做，否则等于给治理留绕过口。

## 4. 页面入口

| 页面 | 地址 | 起服务 |
|---|---|---|
| 交付看板 + 治理管理 | `http://127.0.0.1:8080/delivery/` | delivery，demo profile |
| Agent 花名册 | `http://127.0.0.1:8081/agents/` | agents，demo profile |
| 裁决控制台 | `http://127.0.0.1:8080/console` | gateway（需配 `INKARMOR_API_TOKEN`） |
| Swagger UI / OpenAPI 3 | `http://127.0.0.1:8080/swagger-ui.html`、`/v3/api-docs` | delivery，启动后可用 |

演示配置放 `application-demo.properties`，**不污染接入方自己的 `application.properties`**；不激活 profile 时以空看板启动。端口被 `SERVER__PORT` 覆盖时用 `--server.port=` 显式指定。

## 5. 运维边界

生产数据库保护、基础设施编排、业务数据备份验证、仓库级密钥扫描、人为操作 AI 检查均属接入方 / Ops 职责，框架不内置（见 `docs/排期与拍板.md` 接入方边界节）。网关的告警、熔断、限额见排期批次六。
