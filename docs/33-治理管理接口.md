# 治理管理接口（V1.17）

面向运维与人工审批的后端接口。本文是接口契约的唯一来源；界面区域划分与交互规格见
[34-UI界面说明.md](34-UI界面说明.md)（设计规格，尚未实现）。

- 代码位置：`towndemontower-spring-starter/src/main/java/com/towndemontower/spring/admin/`
- 装配开关：`towndemontower.admin-api-enabled`（默认 `false`）
- 统一前缀：`/towndemontower/admin`

## 1. 开启与鉴权

```yaml
towndemontower:
  admin-api-enabled: true
  metrics-token: ${GOVERNANCE_ADMIN_TOKEN}
```

- 访问令牌复用观测端点的 `towndemontower.metrics-token`，请求头 `X-Governance-Token`。
- **未配置令牌 → 403 `ADMIN_API_DISABLED`**（"开了接口却没配令牌"按拒绝处理，不默认放行）。
- 令牌错误或缺失 → 401 `UNAUTHORIZED`。
- 令牌比较使用定长比较（`MessageDigest.isEqual`），不做前缀短路。
- 接口默认不装配：未显式打开时，连 Controller Bean 都不存在。

## 2. 统一响应格式

```json
{ "code": 0, "message": "ok", "data": { }, "error": null }
```

失败时 `code` 取 HTTP 状态码，`data` 恒为 `null`：

```json
{ "code": 400, "message": "approver 不能为空", "data": null, "error": "VALIDATION_FAILED" }
```

- 前端按 `error` 分支，不要按 `message` 文本匹配。
- 成功判断用 `code == 0`，同时 HTTP 状态为 200。

### 错误码

| error | HTTP | 含义 |
|---|---|---|
| `ADMIN_API_DISABLED` | 403 | 管理接口已开，但未配置令牌 |
| `UNAUTHORIZED` | 401 | 令牌缺失或错误 |
| `BAD_REQUEST` | 400 | 参数类型不匹配、请求体无法解析 |
| `VALIDATION_FAILED` | 400 | 必填字段为空 |
| `INVALID_PARAMETER` | 400 | `limit` / `offset` 越界 |
| `INVALID_STATUS` | 400 | 状态过滤值未知 |
| `SELF_APPROVAL` | 400 | 申请人 / 提交计划的 agent 自批 |
| `NOT_FOUND` | 404 | 单据或计划不存在 |
| `SPOOL_DISABLED` | 404 | 同步暂存区未启用 |
| `CONFLICT` | 409 | 状态已变更（并发或超时） |
| `NOT_PENDING` | 409 | 审批单已决策，不能再次决策 |
| `PLAN_REJECTED` | 409 | 计划已被否决，不能补批 |
| `INTERNAL_ERROR` | 500 | 未预期异常（详情只进服务端日志） |

## 3. R3 人工审批单

对应 `ApprovalCenter`：高风险操作被风险闸门拦下后登记的单据。

### GET `/towndemontower/admin/approvals`

| 参数 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `status` | query | 否 | `PENDING` / `APPROVED` / `DENIED` / `EXPIRED`，忽略大小写 |

```json
{
  "total": 2,
  "items": [
    {
      "id": "T-...", "taskId": "task-9", "tool": "deployService",
      "riskLevel": "R3", "impactNote": "影响线上", "rollbackPlan": "可回滚",
      "requestedBy": "requester", "status": "PENDING",
      "createdAt": "2026-11-05T05:24:15Z", "deadline": "2026-11-05T06:24:15Z",
      "approver": null, "comment": null, "decidedAt": null
    }
  ]
}
```

### GET `/towndemontower/admin/approvals/{id}`

单条详情，字段同上。不存在 → 404 `NOT_FOUND`。

### POST `/towndemontower/admin/approvals/{id}/approve`

```json
{ "approver": "reviewer", "comment": "同意" }
```

- `approver` 必填；等于 `requestedBy` → 400 `SELF_APPROVAL`。
- 非 `PENDING` → 409 `NOT_PENDING`。
- 检查与决策之间状态变化（并发 / 刚好超时）→ 409 `CONFLICT`，`message` 带当前状态。
- 成功返回更新后的单条详情。

### POST `/towndemontower/admin/approvals/{id}/deny`

请求体与规则同上；成功返回 `status=DENIED` 的单据。

> 不提供"建单"接口：单据必须由治理链在拦截时生成，管理面代建等于绕过闸门。

## 4. 执行计划审批

对应 `PlanApprovalService`：`PLAN_APPROVAL_REQUIRED` 闸门拦下任务后生成，批准的是任务范围内的工具集合。

### GET `/towndemontower/admin/plans`

| 参数 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `status` | query | 否 | `PENDING` / `APPROVED` / `REJECTED` |
| `agentId` | query | 否 | 精确匹配 |
| `taskId` | query | 否 | 精确匹配 |

按提交时间升序返回：

```json
{
  "total": 1,
  "items": [
    {
      "id": "P-...", "agentId": "agent-a", "taskId": "task-1",
      "status": "PENDING", "summary": "重构登录模块",
      "requestedAt": "...", "decidedAt": null, "decidedBy": null, "note": null,
      "plan": { "summary": "重构登录模块", "steps": [ { "tool": "...", "intent": "..." } ] }
    }
  ]
}
```

### GET `/towndemontower/admin/plans/{id}`

不存在 → 404 `NOT_FOUND`。

### POST `/towndemontower/admin/plans/{id}/approve`

```json
{ "approver": "reviewer", "note": "同意" }
```

- `approver` 必填；等于计划提交的 `agentId` → 400 `SELF_APPROVAL`。
- 已批准 → 幂等返回当前单（200）。
- 已否决 → 409 `PLAN_REJECTED`（必须让 agent 重新提交计划）。

### POST `/towndemontower/admin/plans/{id}/reject`

请求体同上；已否决时幂等返回。

> 不提供"代提交 / 代修订"接口：计划必须由 agent 在任务执行中提交，否则"谁提的计划"失去意义。

## 5. 审计查询（只读）

### GET `/towndemontower/admin/audit`

| 参数 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `action` | query | 否 | 精确匹配（忽略大小写） |
| `q` | query | 否 | `payload` 子串匹配 |
| `limit` | query | 否 | 默认 100，范围 1..500 |
| `offset` | query | 否 | 默认 0，不能为负 |

```json
{
  "total": 3, "limit": 100, "offset": 0,
  "items": [ { "seq": 42, "action": "ADMIN_API_TEST", "hash": "...", "payload": "..." } ]
}
```

- 审计记录只存"序号 + 动作 + 哈希 + 内容"，**没有独立时间字段**；时间信息由写入方决定是否放进 payload。
- 通过 `offset` 翻页；`offset` 超出总数返回空 `items`，`total` 不变。

### GET `/towndemontower/admin/audit/verify`

```json
{ "valid": true, "records": 42, "anchorRecords": 42, "anchorLag": 0, "replicaFailures": 0 }
```

- `valid=false` 表示整链重算失败（被改写过）。
- `anchorLag` 是尚未进外锚的条数；批量追平模式下大于 0 属正常。
- `anchorRecords` / `anchorLag` / `replicaFailures` 仅在文件审计存储下返回。

## 6. 同步暂存区运维（V1.16）

### GET `/towndemontower/admin/sync-spool`

| 参数 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `limit` | query | 否 | 待补传条目上限，默认 50，范围 1..200 |

```json
{
  "dir": ".../audit.log.spool",
  "stats": {
    "pending": 2, "pendingBytes": 512, "dead": 0, "deadBytes": 0,
    "captured": 2, "retried": 0, "delivered": 0, "failed": 0,
    "deadLettered": 0, "dropped": 0, "skipped": 0
  },
  "pendingTotal": 2,
  "items": [
    {
      "file": "spool-1793...-1.rec", "replica": "http://collector/anchor",
      "attempts": 0, "createdAt": "2026-11-05T05:24:15Z",
      "lastError": "HTTP 503", "snapshot": "records=...&hash=...&mac=..."
    }
  ]
}
```

### GET `/towndemontower/admin/sync-spool/dead`

死信（补传次数达上限、等待人工补传）；字段同 `items`，外层为 `deadTotal`。

### POST `/towndemontower/admin/sync-spool/retry`

立即补传一轮（与定时任务同一逻辑）：

```json
{ "delivered": 2, "retrying": 0, "deadLettered": 0, "skipped": 0 }
```

### POST `/towndemontower/admin/sync-spool/cleanup`

立即按"时间 + 容量"双阈值清理：

```json
{ "droppedByAge": 0, "droppedBySize": 0, "remaining": 2, "remainingBytes": 512 }
```

暂存区未启用（非文件存储 / 无锚点副本 / 关闭 `audit-sync-spool-enabled`）→ 404 `SPOOL_DISABLED`。

> 不提供"删除待补传记录"与"修改快照"：暂存的是尚未送达的证据，管理面能删就能悄悄抹掉一次同步失败。死信只能在文件系统层人工处理。

## 7. 调用示例

```bash
TOKEN=***
curl -s -H "X-Governance-Token: $TOKEN" \
  "http://localhost:8080/towndemontower/admin/plans?status=PENDING"

curl -s -X POST -H "X-Governance-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"approver":"reviewer","note":"同意"}' \
  "http://localhost:8080/towndemontower/admin/plans/P-123/approve"

curl -s -X POST -H "X-Governance-Token: $TOKEN" \
  "http://localhost:8080/towndemontower/admin/sync-spool/retry"
```

## 8. 刻意不开放的接口

以下操作只保留在代码 / 配置层，不提供 HTTP 入口：

- 模式切换（`ModeStateMachine`）：状态推进必须由业务事件驱动；
- 权限授予 / 回收（`PermissionEngine`）：应走审批流，不能做成"点一下就授权"；
- 放行 R3、绕过闸门、关闭审计、签发 `GovernancePass` 令牌；
- 删除待补传记录、改写审计链、修改锚点副本必选语义。
