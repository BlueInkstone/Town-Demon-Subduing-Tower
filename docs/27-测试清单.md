## 0. 优先级定义与执行方式

| 优先级 | 含义 | 失败后果 |
|---|---|---|
| **P0** | 关键路径 / 安全底线 | 阻断发布。涉及权限裁决、审计完整性、认证鉴别、fail-closed 行为 |
| **P1** | 主要功能与重要边界 | 当版修复。影响可用性、证据强度或运维可操作性 |
| **P2** | 次要功能、可观测、健壮性 | 可排后，但需在账上 |

状态标记：`✅ 已覆盖`（有可执行用例且实测通过）/ `⚠️ 部分`（有机制但断言不完整）/ `⬜ 待补`。

执行方式（离线环境）：

```bash
# core / gateway：用 JRE 8 跑（class 52）；starter / delivery / agents：用 JDK 17 跑（class 61）
# 两种都能跑 class 52，但 class 61 的产物在 8 上起不来——跑之前先确认产物版本对得上
java -Dfile.encoding=UTF-8 \
  -cp "target/classes;target/test-classes;$(cat cp.txt)" com.towndemontower.core.V15HardeningTest

# delivery / agents：同上，含真实 Tomcat
```

每次改动 core 或 starter 后**必须手工重装 jar**（`mvn install` 在离线环境不可用），否则下游模块跑的是旧产物。

手动重装 core jar 的标准步骤（替代 `mvn install`）：

```powershell
# ① 带 --release 8 与 -parameters 重编主代码（切面按形参名映射，缺了会假绿；
#    漏掉 --release 8 会按本机 JDK 出 65/69 字节码，装进 m2 后下游在 JRE 8 上直接崩）
javac --release 8 -encoding UTF-8 -parameters -cp "target\classes;$(Get-Content cp.txt -Raw)" -d target\classes `
  (Get-ChildItem src\main\java -Recurse -Filter *.java).FullName
# ② 重打包，并覆盖本地仓库产物
jar cf target\towndemontower-core-0.1.0.jar -C target\classes .
jar cf "$env:USERPROFILE\.m2\repository\com\towndemontower\towndemontower-core\0.1.0\towndemontower-core-0.1.0.jar" -C target\classes .
# ③ 用新 jar 校验条目（应能看到新版本才有的类）
jar tf "$env:USERPROFILE\.m2\repository\com\towndemontower\towndemontower-core\0.1.0\towndemontower-core-0.1.0.jar" | Select-String "PlanApprovalStore|TimeProvider|AuditSyncSpool"
```

手工跑时有三个坑：①`cp.txt` 里引用的 `~/.m2/.../towndemontower-core-0.1.0.jar` 若未按上一步重装，就是旧产物，此时 classpath 必须把 `towndemontower-core/target/classes` **放在它前面**（否则会报 `ClassNotFoundException: PlanApprovalStore`）；②`V115R4EntryTest` 要反射读 `AgentController` / `DeliveryController`，classpath 还需加上 `towndemontower-agents/target/classes` 与 `towndemontower-delivery/target/classes`——**不能用 pom 依赖解决**：这两个模块本身依赖 starter，反向声明会形成循环依赖；③模块级测试只能带"自己 + core + starter"，**不能把 delivery 与 agents 同时塞进同一条 classpath**——两者各自暴露 `OpenAPI` Bean，混在一起会让 `springdoc` 报 `expected single matching bean but found 2: agentsOpenApi,deliveryOpenApi`。

## 9. 回归口径（每次改动后必须执行）

1. 改 core → 手工重装 core jar；改 starter → 手工重装 starter jar（否则下游跑旧产物）。
2. 跑受影响模块全量，再跑**全仓 1575**；不达标不合并。改完 core 后另跑一次 `BypassScanMain --root .`（应为 0 违规，当前覆盖 263 个文件）。
3. 至少连跑两遍，确认幂等（历史上锚点、副本、绑定顺序都出现过"第一次过、第二次挂"）。
4. 有任何 fail → 先判断是"实现错"还是"测试口径过时"；**修检查还是修测试，要在提交说明里写清**（v1.9.2 的日志轮转口径就是典型例子）。
