# 实现记录

> 合并自原 `docs/09`~`docs/13`、`docs/20`~`docs/26`、`docs/29`~`docs/32`。按版本记「做了什么能力、关键约束」，不复述测试数字（见 `docs/测试清单.md`）。架构与机制原文见 `docs/架构方案.md`。

## Phase 1.2 · Runtime & Infra 增强（原 09）

把桩变真实运行时：`CancellationToken` 急停、`PipelineState` 文件落盘、`CredentialBroker`（明文仅在 inject 瞬间存在）、进程级沙箱、AST 管道 + 子 shell 覆盖。均在 core 纯 Java，未触碰 starter，旧链默认行为不变；提供 `SandboxStrategy` 解耦点。

## Phase 1.2.1 · Docker 容器沙箱（原 10）

`--rm -i` / `--network none` / `--memory` / `--cap-drop ALL` / `--read-only`，集中拼装便于审计。复用 `SandboxStrategy` 解耦点，装饰器链零改动，仅替换最内层 Executor；docker 不可用优雅降级为 `SANDBOX_UNAVAILABLE`。

## Phase 1.2.1 · 事务一致性（原 11）

Transactional Outbox：决策落库与 Outbox 同事务原子提交，AFTER_COMMIT 发布 + 5s 轮询兜底。WS 为内存总线等价实现，生产可换 STOMP；超 `MAX_RETRY` 停重试交告警。无 DataSource 退回旧内存行为。

## Phase 1.3 · 交付进度看板（原 12）

新增 `towndemontower-delivery`：交付项 CRUD、状态筛选、整体进度汇总，写操作接 core 治理链。**状态是纯函数实时推导字段而非存储字段**，避免定时任务失效导致看板撒谎；保留人工覆盖并可清除。不做多租户（tenantId 恒 default）、字段级变更留痕、分角色权限。

## Phase 1.4 · Agent 注册表（原 13）

`agentId` 从裸字符串变为有档案的注册对象（ID / 角色 / 技能 / 权限 / 状态）；身份即权限主体，状态流转即授权/回收。本期只做单 Agent 注册管理，只 REST + Swagger；**不做团队 / 汇报关系 / 编排、不做页面**（有回归断言守住）。改档覆盖式授权，SUSPENDED/RETIRED 整员回收，写操作全进审计链。

## v1.6 · 默认安全配置（原 20）

原则：不配置也不降低安全性，放松须显式写出并被自检记录、审计留痕。新增 `FileAuditStore` 落盘、`RejectAllExecutor` 熔断（关闭治理 = 全拒）、`IntentArgsValidator` 输入校验、错误信息与快照脱敏、观测端点令牌鉴权。不在本期：内核/OS 隔离、REST 认证、审计 HMAC 外锚、治理引擎内部故障专属强拦截异常。

## v1.7 · 过渡宽限与门禁密钥（原 21）

`enabled=false` 由全放行改为全拒绝属破坏性变更，给一次性告警放行宽限（首次拦下告警放行、之后熔断）；显式 `disabled-behavior=allow` 视为知情弃权记 CRITICAL。门禁密钥只认环境变量 `TOWNDEMONTOWER_GATE_KEY`，删除系统属性回退与内置 DEV_KEY，缺失/过弱 fail-closed。Docker 默认非 root（`--user 65534`）+ pids-limit，`extraArgs` 越界构造期抛异常。

## v1.8 · REST 调用者认证（原 22）

解决 `/api/**` 零身份校验（任何人可注册自带写权限 Agent）。三档 `loopback` / `token` / `off`；令牌来自 `TOWNDEMONTOWER_API_TOKENS`，≥32 字符 ≥12 种字符，内存只存 SHA-256 定长比较。默认不选 token 是为避免「升级即炸」；读不设令牌按读写分级更易启用。

## v1.9 · 授权收口（原 23）

按「解耦 + 串行」执行：`PermissionEngine` 三个写方法收为包内可见，新增 `PermissionProvisioner` 为唯一写入口，包外直调编译不过。凭据绑定拆为 I3-b、审计加固拆为 I4，全量回归通过后才动下一刀，不做并行。

## v1.9.1 · 凭据与 Agent 绑定（原 24）

解决「你是哪个调用者」≠「你代表哪个 Agent」。用 `TOWNDEMONTOWER_API_BINDINGS` 建立令牌名 → Agent 映射，绑定后 `ctx.agentId` 变为具体 AGT，RBAC 按其裁决、审计归属到它。只读环境变量，不落配置文件。

## v1.9.2 · 审计写入收权与锚点追平（原 25）

删公开 `append`，改 `appendAuto` 由存储自算 seq/prevHash/hash，调用方只提供「发生了什么」，伪造 Record 进不了链。外锚由每写一条落盘改批量追平；不改变链语义，只改变「谁有能力制造证据」。

## v1.10 · 锚点副本与回滚检出（原 26）

补「整目录回滚」攻击——本地链自洽、锚点 MAC 正确时本地无法发现回滚。加本机之外副本（file/offhost/https）作外部参照记住写到第几条；副本不可读默认拒绝（`replica-required=true`）。挡不住副本收集端本身被删。

## v1.11 · 绕过治理令牌与静态扫描（原 29）

把「经过治理链」从约定变前置条件：`GovernancePass` 链尾唯一发牌、方法首行 `require` 消费、finally 收回，未经过则执行不了且留痕计数。静态扫描五规则构建期失败。不做内核级强制、不新增依赖、不改 CI 配置（只交付判据）。

## v1.12 · 命令模板化（原 30）

把「命令危不危险」不可判定问题换成「是否符合工具声明形状」可判定问题：声明 `commandTemplate`，不符即 `COMMAND_TEMPLATE_MISMATCH`。AST 正则黑名单保留为第二道防线。

## v1.13 · 执行计划审批（原 31）

补上一直无产生方的 `PLAN_APPROVAL_REQUIRED`：高风险工具声明 `requiresPlanApproval=true`，先提交任务级计划、由非提交者人工批准，仅 APPROVED 才放行；缺省 false 对存量零影响。

## v1.14 · 计划回放与结构化（原 32）

计划升级为 `PlanArtifact` + `PlanStep`，批准范围从任务级收紧到「只放行点名的工具」；空意图步骤不放行任何工具（「看看再说」不是空白支票）。request 对已批准任务幂等，扩范围须显式 `revise`；旧格式仍按任务级放行，旧调用方零改动。
