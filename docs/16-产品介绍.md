# Town Demon-Subduing Tower · 产品介绍（v1.4）

## 一句话定位

给 Agent 装**刹车和行车记录仪**的 Java 治理层：Agent 每调用一个工具，都必须经过一条固定的 10 环节检查链；事后每一次调用（包括被拒绝的）都能在不可篡改的哈希链里查到。

## 它解决什么

Agent 已经能写文件、跑命令、发部署。让人不敢放手的从来不是"它不够聪明"，而是三件事没人能回答：**它改坏了什么、谁让它改的、能不能收回来**。这三件事靠提示词、靠日志、靠事后读代码，都回答不了。

## 主要能力

| 能力 | 具体形态 |
|---|---|
| **治理链** | 10 环节固定顺序：审计 → 模式白名单 → 意图格式 → Schema → 能力 → RBAC → 风险闸门 → 污点检查 → 快照 → 沙箱 |
| **Agent 注册表** | ID、角色、技能、权限、状态。档案里的"应然权限"与 RBAC 里的"实然权限"可逐项对账，停用/注销立即整员回收 |
| **可追溯** | SHA-256 追加写审计链，任何分支（含被拒调用）都留痕，链可校验 |
| **可回滚** | 有副作用的工具执行前留快照 |
| **可观察** | 交付进度看板（13 条本产品真实里程碑）、OpenAPI 3 + Swagger UI（Agent 注册表仅 REST，无页面） |

## 价值：四件事

**能查**——谁、在什么模式、用什么工具、参数是什么、被哪个环节拒的。
**能拦**——R2 转人工审批、R3 直接拒绝、污染会话禁止写与外发。
**能回**——写前快照，改坏了有现场。
**能收**——Agent 停用或注销，权限当场失效，不留后门。

## 目标用户

**适合**：个人开发者与 1~3 人小队；正把 Agent 从"聊天"接到"动真格"（写文件、跑命令、部署）；技术栈是 Java / Spring Boot；认同"治理应当是固定管线，而不是可拖拽的图形"。

**不适合**（当前版本确实做不到）：需要可视化流程设计器的场景；需要多 Agent 协作与任务派发的场景；需要多租户隔离、账号体系、多人审批的团队协作场景。

## 相较以往的改进

1. **主体从"裸字符串"变成"有档案的注册对象"**。v1.0~v1.3 里 `agentId` 只是调用方随手传的字符串，权限散落在各处装配代码中，只授不撤。v1.4 引入 Agent 注册表：ID 即身份，注册授予、改档覆盖式（不残留旧角色权限）、停用注销整员回收，接口同时返回应然与实然权限并标记是否一致。

2. **看板从"演示数据"变成"自身真实进度"**。13 条里程碑的时间逐条取自仓库真实文件时间戳，打开看板即知这个产品做到哪一步，而不是看一份虚构样例。

3. **工程完备度**：补齐 OpenAPI 3 + Swagger UI（静态资源走本地 webjar，零 CDN，离线可用）；测试从 308 项增至 **509 项全绿**；core 始终保持零外部依赖（仅 JDK 21）。

## 明确不是什么

不是可视化编排平台，也不是多 Agent 协作引擎。编排层（`agenthub.yml` / `@Flow` / 单文件脚本三种形态）目前是**设计稿**，尚未实现——这一点写在文档里，而不是写进功能列表。
