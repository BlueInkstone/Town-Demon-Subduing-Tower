# 架构方案

> 合并自原 `docs/02`（架构方案）、`docs/06`（适配层设计）、`docs/07`（伪代码）、`docs/14`（流程设计）、`docs/18`（防绕过）。本文是架构与设计约束的**唯一权威出处**。

## 1. 分层与依赖

```
任意语言客户端 / 宿主应用
  ├─ 网关形态：POST /api/evaluate → core 评估链（只裁决、不执行）
  └─ 嵌入式：@AgentSkill + AOP 切面 → core Executor（裁决 + 执行）
                                      ↓
                          towndemontower-core（纯 Java，零 Spring）
```

- **core 纯 Java、零 Spring**：禁止 `import org.springframework.*`；契约语言中立（JSON、禁 Optional/CompletableFuture/Java 序列化）。
- **starter 薄适配层**：只做「翻译 + 装配 + 暴露」，不改 core 一行代码。切点命中 → 懒注册 `SkillDescriptor` → 构造 `IntentObject`/`ExecutionContext` → 绑定 `pjp.proceed()` → `executor.execute()`。拒绝抛 `GovernanceDeniedException`（带 code 与审批单号）。
- 条件装配全部 `@ConditionalOnMissingBean` 可覆盖——既是扩展点也是绕过面，需显式声明留痕。
- 编译/运行基线两档：core / gateway = Java 8（class 52）；starter / delivery / agents = Java 17（class 61）。不要抬到 21/25（Spring Boot 3.2.5 内嵌 ASM 读不了 class 69）。

## 2. 固定流程 + 可插拔策略（原 docs/14）

「骨架焊死、肌肉可换」：10 环节顺序写死，无配置项、无扩展点，只能改源码。

```
IntentObject
  → ModeToolPolicy（模式白名单）
  → IntentFormat（格式 + 置信度）
  → Schema / Capability
  → Permission（RBAC）
  → RiskGate（R0-R3 + AST + 复合取最高）
  → ApprovalRequired（R2 挂人工）
  → TaintCheck（污点写阻断）
  → Snapshot（写前快照）
  → SandboxedTool（沙箱执行）
  → Audit（哈希链，任何结果都记录）
```

- 顺序有依赖：Audit 最外、Mode 在 Schema 前、Permission 在 RiskGate 前、Snapshot 在 Sandbox 前；交换会致漏洞或误判。
- 「跳过某环节」只能靠恒真策略降级——改语义不改拓扑。
- 模式状态机刻意无 `AUDIT_REVIEWING → DEV_EXECUTION` 直连，必须 `REPLAN`，为最重要流程约束。
- 面向单人 + 单 Agent 串行；团队协作地基具备但闭环未补齐。

## 3. 防绕过设计（原 docs/18）

- 不做内核级强制（需 sidecar/eBPF，超出产品形态）；只做三件事：**无痕 → 有痕、默认可用 → 默认被拒、靠自觉 → 可验证**。
- 对手模型：A 误用者（主战场，要拦）、B 越权开发者（要看得见）、C 未认证调用者（要进不来）、D 宿主 root（不设防，只求事后发现）。
- 四个转变：注解 → 能力令牌（`GovernancePass` 一次性令牌，链尾发牌、方法首行收牌、finally 收回）；关开关 = 全拒绝（fail-closed）；策略替换须显式声明留痕；审计 HMAC + 进程外锚点。
- 已落地：审批中心、门禁密钥仅环境变量、启动自检（CRITICAL 拒启）、REST 调用者认证、审计 HMAC 外锚、命令模板、Docker `extraArgs` 白名单、构建期静态扫描。

## 4. 关键机制

| 机制 | 做法 |
|---|---|
| **风险分级** | R0 放行 / R1 轻确认 / R2 人工审批 / R3 默认拒绝（带 `--force` 也不放行） |
| **命令模板** | 工具声明 `commandTemplate`：字面量固定、参数只落 `{...}` 槽位、禁多余词与控制符、单值槽禁 `-` 开头；AST 黑名单保留为第二道 |
| **计划审批** | `requiresPlanApproval=true` → 先提交任务级计划、非提交者人工批准；`PlanArtifact`/`PlanStep` 把范围收紧到点名工具，空步骤不放行；旧格式仍按任务级放行 |
| **事务一致性** | `@Transactional` 决策落库 + Outbox 同事务提交，AFTER_COMMIT 发布 + 5s 轮询兜底；有 `DataSource` 才启用，无则退回内存 |
| **审计链** | 追加写 + SHA-256/HMAC；`appendAuto` 由存储自算 seq/prevHash/hash，调用方只提供「发生了什么」；外锚 + 本机之外副本防回滚；副本不可读默认拒绝 |
| **身份与权限** | `agentId` 为注册表中有档案的对象；应然权限（档案）与实然权限（生效）逐项对账；改档覆盖式授权，停用/注销整员回收 |
| **调用者认证** | 三档 `loopback`（默认，读放行、写仅本机）/ `token`（Bearer，令牌来自环境变量，内存只存 SHA-256）/ `off`（仅外层网关已鉴权，启动记 SEVERE 告警） |

## 5. 构建期自检（`BypassScanMain`，零依赖）

五规则：注解目标 / 方法体副作用 / 首行令牌（BLOCKER），Controller 直调 / 模板过宽（WARN，可显式豁免、`--strict` 下阻断）。退出码 0=通过、1=违规、2=用法/IO 错；`--report` 产 SonarQube 通用问题报告。
