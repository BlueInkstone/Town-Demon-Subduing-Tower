## 3. 接入方边界（只写说明、不占实现）

普通/管理员权限分离（框架只给 RBAC + 管理令牌，管理员角色由接入方在注册表授予）、生产数据库保护、密钥不进 Git 的仓库级扫描、人为操作 AI 检查（不引入模型判定）、数据库/基础设施/部署、通用备份验证——均属接入方 / Ops 职责。

## 5. 方向 C · 审计驱动的动态防御（原 docs/36）

- **M1 只读行为报告**：✅ 已实现。纯 Java 零依赖；默认关闭、离线 CLI；零权限/模式/闸门变更；扫描前后审计链哈希不变；只认 Java 规范码，可加 `--normalize-aliases` 归一别名。分析器**永不裁决、只提议**。
- **M2 降权建议单**：✅ 已批准并排期，待架构设计。建单只能由分析链生成（无管理端点建单口）；复用 `ApprovalCenter` 禁自批；批准后显式下发、到期回收可回滚；全链路留痕。
- **M3 后台自动收紧**：❌ 明确否决，不排期、非候选。
- 已否决：追求自动提升拦截率 / 实时 / 智能（LLM 判定）、把审计链改造成控制总线。SDK 链纳入 M1、跨语言 golden、本期 UI 均否决或排后。

## 6. 排期约束

- **不做的事不复活**：后台自动收紧、管理端点建单、模型判定、第二回报接口、`delivery`/`agents` 改造，任何后续评审都不作为候选。
- **文档不撒谎**：形态未落地不写「任意语言可接入」；内部故障强拦截未落地不写「绝不静默失效」；基线未整轮重跑如实标注。
- **全仓回归整轮实跑**是合并前验证项，属 QA 执行，不占批次；基线数字与口径见 `docs/测试清单.md`（唯一出处）。
- 本排期只定顺序与交接，不承诺日期。
