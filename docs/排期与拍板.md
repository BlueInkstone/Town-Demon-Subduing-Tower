## 6. 检索查询语法契约（2026-11-26 定稿，批次九）

> 现状：6 处检索各写各的——审计 `action/q/from/to/limit/offset`、审批 `status`、计划 `status/agentId/taskId`、Agent `status/role/keyword/drift`、交付 `status`、暂存区 `limit`；无统一 DSL，分页能力不齐。语法要解决的是**统一参数语义 + 允许组合条件**，不是做完整查询语言。

**语法（只用 5 类符号）**

```
field=value      精确        action=R3_DENIED
field~value      包含        payload~删除
field>value      比较        seq>100、ts>2026-11-26T00:00:00Z
-fields          排除        -status=PENDING
field=(a|b)      多值        status=(PENDING|APPROVED)
```

- 条件间**空格 = AND**；**不支持 OR 与嵌套括号**（复杂度主要来源，先不做）。
- 字段按域白名单：审计 `action/payload/agent/task/ts/seq`；审批 `status/requestedBy/tool`；Agent `status/role/keyword/drift`；交付 `status/owner`。
- `limit/offset` 留在普通查询参数，不进语法串。

**复杂度硬边界**

| 约束 | 值 | 理由 |
|---|---|---|
| 字段 | 白名单，未知字段报错 | 防查到不该暴露的审计内部字段 |
| 子句数 | ≤ 8，布尔仅 AND + 前缀 `-` | 无嵌套 = 无优先级歧义，无需括号解析器 |
| 串长 | ≤ 512 字符 | 防 DoS |
| 值 | 只标量；禁正则、禁 `*`、`禁函数` | 避免变成另一个注入面 |
| 时间 | 固定 ISO 8601 定长 | 不解析自然语言，可复算 |
| 解析结果 | 纯数据 AST，服务端校验 | AI 输出必须过解析器，不直接执行 |
| 执行 | 先看 AST 再查询，带超时 | 「告知后果」——回显解析结果供确认 |

**AI 生成边界**：AI 只做「自然语言 → 语法串 + 一句说明」，不直连数据源、不生成 SQL/代码。服务端提供 `parse/explain`（REST 或 CLI）把语法串解析成 AST 回显，用户看到「查的是审计域、action=R3_DENIED、limit=100」再决定是否执行。校验失败返回字段级错误，不静默放宽。与计划审批同模式：**AI 提议、闸门裁决、人确认**。

**先接两个域试点**：审计查询（组合筛选需求最强）、Agent 筛选（`drift` 现仅前端有，借统一语法补服务端）。不动治理链、不动审计链格式，纯查询侧改动。

## 7. 排期约束

- **不做的事不复活**：后台自动收紧、管理端点建单、模型判定、第二回报接口、`delivery`/`agents` 改造，任何后续评审都不作为候选。
- **文档不撒谎**：形态未落地不写「任意语言可接入」；内部故障强拦截未落地不写「绝不静默失效」；基线未整轮重跑如实标注。
- **全仓回归整轮实跑**是合并前验证项，属 QA 执行，不占批次；基线数字与口径见 `docs/测试清单.md`（唯一出处）。
- 本排期只定顺序与交接，不承诺日期。
