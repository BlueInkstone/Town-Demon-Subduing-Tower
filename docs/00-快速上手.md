# 快速上手（v1.4）

> 目标：**10 分钟内**看到两个可用的看板，并把治理接进你自己的 Spring Boot 项目。
> 全程不需要数据库、不需要 Docker、不需要联网。

---

## 0. 你需要什么

| 项 | 要求 | 说明 |
|---|---|---|
| JDK | **17**（看板类）/ **8**（仅 core 或 gateway） | 编译目标只有两档：`core`、`gateway` 是 Java 8（class 52），`starter`、`delivery`、`agents` 是 Java 17（class 61）。只用 Java 8 的接入方走 core 直调或 gateway HTTP，**用不了 starter 的注解与 AOP**。不要用 21/25 编译，也不要把三个 Spring 模块抬到 21/25 |
| Maven | 3.9+ | 离线模式需本地仓库已缓存依赖（本仓库已具备） |
| 数据库 | 不需要 | 无 DataSource 时 tx 模块自动跳过 |
| Docker | 不需要 | 容器沙箱是可选能力，缺失时降级为 `SANDBOX_UNAVAILABLE` |
| 网络 | 不需要 | 全体依赖已缓存，加 `-o` 走离线 |

目录约定（下文的相对路径都以仓库根为准）：

```
towndemontower-core            治理内核（纯 Java，零外部依赖）
towndemontower-spring-starter  Spring 适配层（@AgentSkill + 自动配置）
towndemontower-delivery        交付进度看板（:8080）
towndemontower-agents          Agent 注册表（:8081，仅 REST，无页面）
```

## 1. 三分钟看到成品

### 1.1 装依赖（只需一次）

```bash
cd towndemontower-core && mvn -o -DskipTests install
cd ../towndemontower-spring-starter && mvn -o -DskipTests install
```

> 若这两条命令报错，直接跳到 [§2](#2-装依赖失败怎么办)，那里有兜底方案。

### 1.2 起两个 demo（两个终端）

```bash
# 终端 A ── 交付进度看板
cd towndemontower-delivery
mvn -o spring-boot:run -Dspring-boot.run.profiles=demo

# 终端 B ── Agent 注册表
cd towndemontower-agents
mvn -o spring-boot:run -Dspring-boot.run.profiles=demo
```

### 1.3 你会看到什么

| 地址 | 内容 |
|---|---|
| <http://127.0.0.1:8080/delivery/> | 13 条**本产品自身**的交付里程碑：6 已完成 / 1 已延期 / 1 进行中 / 5 未开始，整体进度 49% |
| <http://127.0.0.1:8080/swagger-ui.html> | 交付看板接口文档（可 Try it out） |
| <http://127.0.0.1:8081/swagger-ui.html> | Agent 注册表接口文档（可 Try it out） |

> Agent 注册表**只提供 REST 接口，没有页面**；访问 `/agents/` 会得到 404。

**值得验证的一件事**：SUSPENDED 与 RETIRED 的 Agent，实然权限为空但档案权限仍在——
这就是 v1.4 的核心：**应然（档案）与实然（生效）分离，且可对账。**

```bash
curl -s http://127.0.0.1:8081/api/agents/summary
# {"total":7,"activeCount":4,...,"permissionCoverage":100.0}

curl -s "http://127.0.0.1:8081/api/agents?status=SUSPENDED"
# effectivePermissions 为空，permissions 仍在
```

## 2. 装依赖失败怎么办

**症状**：`PluginResolutionException`，提示 `maven-surefire-common` 无法解析，或离线时 `present, but unavailable`。

**原因**：`mvn install` 会执行 test phase，而 JDK 21 下 surefire 3.2.5 在本机无法解析。
`-DskipTests` 只跳过测试**执行**，不跳过插件**解析**，所以照样失败。

**解法（手工装 jar，3 条命令）**：

```bash
cd towndemontower-core
rm -rf out-main
# 必须带 --release 8：否则按本机 JDK 版本出字节码，下游在 JRE 8 上会 UnsupportedClassVersionError
javac --release 8 -encoding UTF-8 -d out-main $(find src/main/java -name "*.java")
jar cf /tmp/towndemontower-core-0.1.0.jar -C out-main .
cp /tmp/towndemontower-core-0.1.0.jar ~/.m2/repository/com/towndemontower/towndemontower-core/0.1.0/
```

> **改了 core 源码后必须重做这一步**，否则下游编译会报"找不到符号"——m2 里还是旧 jar。

## 3. 网关形态（非 Java 语言走 HTTP）

> 形态说明见 `docs/38-网关形态改造范围.md`。网关形态不要求 Java / Spring Boot：只要能发 HTTP，10 分钟内拿到裁决。

### 3.1 起网关（本地两条命令）

```bash
cd towndemontower-core    && mvn -o clean install -DskipTests
cd ../towndemontower-gateway && mvn -o clean package

# 运行（令牌必配，否则所有请求 403）
INKARMOR_API_TOKEN=你的令牌 PORT=8080 \
  java -jar target/towndemontower-gateway-0.1.0.jar
```

产物是 thin jar + `target/lib/`，**两者要一起拷走**；`clean` 不能省——增量编译会把旧 JDK 编的高版本
字节码打进分发包，在 Java 8 上启动即失败。细节与配置项见 `docs/39-网关接入指南.md`。

### 3.2 发一个意图（任意语言）

请求体只有 `IntentObject` 6 个字段（`tool` / `args` / `confidence` / `reason` / `expectedEffect` / `rollbackHint`），可选 `context` 覆盖 `agentId` / `mode` / `tainted` 等。
**必须带令牌头 `X-Inkarmor-Token`**，否则 401：

```bash
curl -X POST http://localhost:8080/api/evaluate \
  -H 'Content-Type: application/json' \
  -H 'X-Inkarmor-Token: 你的令牌' \
  -d '{"tool":"restartService","args":{"service":"svc-1"},"confidence":0.9,
       "reason":"例行重启","expectedEffect":"服务重启","rollbackHint":"无"}'
# 返回：{"code":0,"message":"ok","data":{"success":true,"code":"OK",
#         "message":null,"output":null,"approvalTicketId":null}}
# 拒绝例：data.code=R3_DENIED；待审批例：data.code=PENDING_APPROVAL + 单号
```

**Python（薄包 `@inkarmor_guard`，标准库零依赖）**：

```python
from inkarmor_guard import inkarmor_guard

@inkarmor_guard("restartService", confidence=0.9, reason="例行重启")
def restart(service: str):
    ...  # 只有裁决为"允许"才会执行到这里；拒绝/不可达都直接抛异常（fail-closed）
```

**Go / Node**：用 `http.Post` / `axios.post` 发同一份 JSON 即可，不发 SDK、不装包。

每一次 `/api/evaluate` 调用都会落审计，**包括**缺/错令牌、非 POST、非法 JSON、请求体超限这些在入口就被挡下的拒绝
（探活 `GET /api/health` 不写，免得探针把审计刷满）。R2 的单号仍只是进程内编号、网关没有批准接口；
并发打满后是排队而不是限流。**网关只裁决、不执行**——真正执行仍在你进程里，按返回的 `data.code` 自行决定要不要继续。
完整的局限清单见 `docs/39` §8。

## 4. 嵌入式形态（Java / Spring Boot）

**最小接入只有三处必需项**——一个依赖、每个工具一个注解、方法首行一行令牌。
下面 4.1 是可直接复制的最小可用版；4.2 起是「完整配置」，按需再加，不是必须写的。
完整配置版的接入代码已由真实冒烟测试验证（`QuickstartSmokeTest`，6/6 通过），走完整自动配置与 AOP，不是手动装配。

### 4.1 最小可用（推荐先跑通）

**① 加依赖**（一次性）

```xml
<dependency>
    <groupId>com.towndemontower</groupId>
    <artifactId>towndemontower-spring-starter</artifactId>
    <version>0.1.0</version>
</dependency>
```

**② 写业务方法：注解 + 一行令牌**

```java
@Component
public class OpsTools {

    @AgentSkill(name = "restart", risk = "R1")
    public String restart(String service) {
        GovernancePass.require("restart");       // 首行：防绕过凭证，不能省
        return "restarted:" + service;           // 业务代码原样写
    }
}
```

**③ 没有第三处**：配置可以一行不写。`enabled` 默认 `true`、`agent-id` 默认 `agent-default`、
`mode` 默认 `DEV_EXECUTION`、租户/会话/任务/所有者都有默认值；不声明 `requiredPerms`
就不需要 `permissions-bootstrap`。

代价说清楚：不写 `requiredArgs` 就没有 Schema 校验，不写 `requiredPerms` 就没有 RBAC，
`risk` 不写会缺省 **R2 → 转人工审批**（最保守，但工具跑不起来，所以上例写了 `R1`）。
首行 `GovernancePass.require("工具名")` 必须写，参数与 `@AgentSkill(name=...)` 逐字一致——
它是证明「这次调用确实从治理链进来」的凭证，同类自调用绕过 AOP 时就靠它挡住；
漏写会被 `CP10-R3` 静态扫描判违规（见 §7）。

### 4.2 完整配置（按需）

需要 RBAC、Schema 校验、快照策略或独立身份时，再往下加。下面两节都是**可选**的，
依赖仍用 4.1 ① 那份即可（starter 会传递 `spring-boot-starter-aop`，无需自己加；
它不传递 JDBC 驱动，所以没有数据库的项目也能正常启动）。

#### 4.2.1 带完整声明的注解

```java
import com.towndemontower.core.decorator.GovernancePass;
import com.towndemontower.spring.AgentSkill;
import org.springframework.stereotype.Component;

@Component
public class OpsTools {

    @AgentSkill(name = "restartService", risk = "R1",
                requiredPerms = {"ops:restart"}, requiredArgs = {"service"})
    public String restart(String service) {
        GovernancePass.require("restartService");   // 首行：凭证
        return "restarted:" + service;               // 业务代码原样写
    }

    @AgentSkill(name = "deployService", risk = "R2",
                requiredPerms = {"ops:deploy"}, requiredArgs = {"target", "version"})
    public String deploy(String target, String version) {
        GovernancePass.require("deployService");
        return "deployed:" + target + "@" + version;
    }
}
```

不必写任何鉴权、审计、快照代码——这些由框架兜底。
首行 `require` 的作用与不能省的理由见 4.1，参数必须与 `@AgentSkill(name=...)` 逐字一致。

注解属性含义：

| 属性 | 默认 | 作用 |
|---|---|---|
| `name` | 必填 | 工具名，`SkillRegistry` 的 key |
| `risk` | `R2` | R0/R1 放行、R2 转审批、R3 直接拒；未知默认 R2 |
| `requiredPerms` | `{}` | 需要的 RBAC 权限 |
| `requiredArgs` | `{}` | 必填参数（与形参名对应） |
| `sideEffect` | `true` | 是否执行前留快照 |
| `sandbox` | `ephemeral` | `read-only` / `ephemeral` / `none` |

#### 4.2.2 配置（可选）

```yaml
towndemontower:
  enabled: true
  agent-id: my-local-agent          # 治理链里的身份
  mode: DEV_EXECUTION               # 仅初始值；运行期由状态机推进
  # 权限必须显式授予（v1.6 起 auto-grant 默认关闭）
  permissions-bootstrap:
    - fs:write
    - ops:restart
```

> **v1.6 起默认不自动授权**：注解里的 `requiredPerms` 只是"声明需要什么"，
> 不再自动授予。不配 `permissions-bootstrap`（或注册表下发）就会 403。
> 这比"默认全授权"多写三行，但换来的是"权限来源唯一且可审计"。

### 4.3 验证：四种典型结局

调用上面两个方法，你会看到：

| 调用 | 结果 | 说明 |
|---|---|---|
| `restart("svc-1")` | 返回 `restarted:svc-1` | R1 通过，业务方法真的执行了 |
| `deploy("web","1.0")` | 抛 `GovernanceDeniedException`，`code=PENDING_APPROVAL`，带 `ticketId` | R2 转人工审批，**业务方法未执行** |
| 声明 `risk="R3"` 的工具 | 抛 `GovernanceDeniedException`，`code=R3_DENIED` | 硬性拒绝，不提供审批通道 |
| 在 `DEV_EXECUTION` 下调 `splitTask` | `code=MODE_TOOL_NOT_ALLOWED` | 模式白名单拦截 |

每次调用（含被拒的）都会落审计链，可用 `AuditStore.verifyChain()` 校验。

## 5. 三个必踩的坑（嵌入式形态）

### 坑一：同类内部调用，注解静默失效

```java
@Component
public class OpsTools {
    public String batchRestart() {
        return this.restart("svc-1");   // ❌ 不走代理，治理完全绕过
    }
}
```

Spring AOP 基于代理，`this.xxx()` 不经过代理。**拆到另一个 Bean 调用**，或注入自身代理。
这类绕过不会报错，只会悄悄没有审计——最危险的一种。

### 坑二：方法必须是 public、非 final、非 static

`private` / `final` / `static` 方法无法被 CGLIB 代理，注解同样静默失效。
v1.11 起这类写法不必等到运行期才发现：`CP10-R1` 会在扫描阶段直接判违规。

### 坑三（嵌入式）：403 不是 bug，通常是没授权

`PERMISSION_DENIED` 意味着当前 `agent-id` 没有 `requiredPerms`。
v1.6 起默认**不自动授权**，两种解法：在 `permissions-bootstrap` 里显式列出权限；
或用 Agent 注册表把权限写进档案（生产推荐）。
只有在明确只要便利不要边界时，才把 `auto-grant-declared-perms` 打开——它会在启动自检里被记为
`AUTO_GRANT_ENABLED`。

## 6. 拒绝码与异常速查（嵌入式形态）

| code | 含义 | 该改什么 |
|---|---|---|
| `PERMISSION_DENIED` | RBAC 未通过 | 授予权限，或检查 `agent-id` |
| `MODE_TOOL_NOT_ALLOWED` | 当前模式不允许该工具 | 换模式，或调整 `ModeToolPolicy` |
| `PENDING_APPROVAL` | R2 转人工审批 | 走审批流程；本地演示可降 risk 到 R1 |
| `R3_DENIED` | R3 硬拒绝 | 设计如此，不要试图绕过 |
| `TAINTED_WRITE_BLOCKED` | 会话已污染，禁止写/外发 | 新开会话或清污染标记 |
| `INTENT_FORMAT_INVALID` / `NEED_MORE_INFO` | 意图不完整或置信度过低 | 补参数、提高 confidence |
| `SANDBOX_UNAVAILABLE` | 沙箱不可用（如缺 Docker） | 换沙箱策略或补环境 |
| `UNGOVERNED_INVOCATION` | 方法首行拿不到令牌：自调用或绕过切面直调 | **不是配置问题**，是调用路径问题：从受治理入口重新调用；补 `GovernancePass.require(...)` 首行 |

**业务异常不会被吞掉**：被治理方法内部抛出的 `RuntimeException` 会原样重抛；
只有"治理拒绝"才包装成 `GovernanceDeniedException`。两者可以据此区分。

## 8. FAQ

| 现象 | 原因 | 处理 |
|---|---|---|
| 端口不是 8080/8081，报 `Port xxxxx was already in use` | 环境变量 `SERVER__PORT` 覆盖了配置 | 命令行显式指定：`--server.port=8081` |
| 看板打开是空的 | 未激活 demo profile | 加 `--spring-boot.run.profiles=demo` 或 `--spring.profiles.active=demo` |
| 重启后数据没了 | 默认内存存储 | 配 `storage=file` + `data-file` |
| 日志里出现 H2 连接 | 你项目里有 H2/JDBC 驱动，tx 模块自动启用 | 正常；不需要事务一致性可排除数据源 |
| 注册 Agent 报 400 `skills` | 技能名不在工具注册表 | 用 `GET /api/agents/meta` 的 `skills` 列表取值 |
| 删除档案报 400 | 未先置 RETIRED | 先 `PUT /api/agents/{id}/status` 设 `RETIRED` |
