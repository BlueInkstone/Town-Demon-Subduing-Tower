## 0. 范围与前置约束

### 0.1 本文覆盖的界面

一个页面、两个页签，替换现有
`towndemontower-delivery/src/main/resources/static/delivery/index.html`：

| 页签 | 数据源 | 操作数量 |
|---|---|---|
| A. 交付看板 | `/api/delivery/**`（7 个端点） | 8 个用户交互（另有首屏 3 个自动请求） |
| B. 治理管理 | `/towndemontower/admin/**`（14 个端点） | 14 个决策/查询操作（筛选、分页、切页签等辅助交互不计入） |

页面地址与现有重定向保持不变：
`/`、`/delivery`、`/delivery/` → `/delivery/index.html`。
因此替换 `index.html` 不需要改 `DeliveryBoardPageController`。

### 0.2 硬约束

1. **零第三方依赖**：不引用 CDN、不引入前端框架，单文件 HTML + 内联 CSS/JS，离线可用。
2. **数据只来自后端**：页面不内置业务数据，不本地推导状态（状态由服务端返回）。
3. **不可操作区域不得发请求**：纯展示区（卡片、表头、详情抽屉、折叠展开）点击无网络请求。
4. **令牌只在会话内**：治理令牌存 `sessionStorage`，键 `twd.adminToken`；不落 localStorage、不写日志、不回显到页面文本以外的地方。
5. **认证默认 loopback**：`/api/*` 读放行、写仅本机；跨机使用需 `auth-mode=token` 并配置 `TOWNDEMONTOWER_API_TOKENS`（见 docs/22）。

### 0.3 后端开启条件

| 页签 | 必需配置 | 未满足时的界面表现 |
|---|---|---|
| A | `towndemontower.delivery.enabled=true`（默认） | 整页 404，无法打开页面 |
| B | `towndemontower.admin-api-enabled=true` 且 `towndemontower.metrics-token` 非空 | 治理页签显示"管理接口未开启"横幅，所有操作禁用，不发请求 |

## 2. 全局区域

### G1 顶部栏

- **展示内容**：产品名"镇妖塔 · 治理控制台"；服务器时间（来自 `GET /api/delivery/meta` 的 `now`，格式 `yyyy-MM-dd HH:mm:ss`，标注"服务器时间"）；令牌状态徽标（"未配置令牌"/"已配置"）。
- **可操作**：点击令牌徽标打开 G1 令牌弹层。
- **交互规则**：服务器时间只在首屏与手动刷新时更新，不做秒级轮询（避免无意义请求）。

### G2 页签导航

- **可操作**：两个按钮切换 A/B 视图，纯前端切换，**零请求**；切换不丢失已加载数据。
- **默认页签**：A。

### G3 全局提示条

- **纯展示**。三种形态：
  - 加载中：骨架/文字"加载中…"，覆盖对应区域；
  - 错误横幅：`error` 码 + `message`，附【重试】按钮（重试按钮属可操作，重发对应请求）；
  - 空态：见 A4、B4 无数据。

### G4 令牌弹层（G1-b 打开）

| 元素 | 属性 | 规则 |
|---|---|---|
| 输入框（password 类型） | 可操作 | 不回显已保存令牌，占位符"治理令牌" |
| 【保存】 | 可操作 | 仅写 `sessionStorage.twd.adminToken`，**不发请求**；关闭弹层，令牌徽标变为"已配置" |
| 【清除】 | 可操作 | 删除 sessionStorage 键，**不发请求**；治理页签立即回到未授权态 |
| 【取消】 | 可操作 | 关闭弹层，不修改 |

未保存令牌时：B 页签所有操作按钮 `disabled`，区域顶部显示"未配置治理令牌"提示，**不发送任何请求**。

## 3. 页签 A：交付看板

### A1 汇总卡片区（纯展示）

8 张卡片，数据源 `GET /api/delivery/summary`：

| 卡片 | 字段 | 类型/格式 | 展示规则 |
|---|---|---|---|
| 整体进度 | `overallProgressPercent` | int 0–100 | 数字 + `%` + 进度条宽度 |
| 交付项总数 | `totalCount` | int | 纯数字 |
| 完成率 | `completedRatioPercent` | int 0–100 | 数字 + `%` |
| 已完成 | `completedCount` | int | 纯数字 |
| 进行中 | `inProgressCount` | int | 纯数字 |
| 已延期 | `delayedCount` | int | 纯数字（>0 时橙色） |
| 未开始 | `notStartedCount` | int | 纯数字 |
| 下一个交付节点 | `nextUpcomingPlannedEnd` | LocalDateTime \| null | `yyyy-MM-dd HH:mm`，null 显示 `—` |

- **交互规则**：整块不可点击，点击不发请求；不做 hover 高亮（避免暗示可点）。
- 数据缺失（字段为 null）统一显示 `—`，不显示 `undefined`/`null`。

### A2 工具栏

| 控件 | 操作 | 请求 | 说明 |
|---|---|---|---|
| 状态下拉 | 选择 | `GET /api/delivery/items?status=<code>` | 选项由 `GET /api/delivery/meta` 的 `statuses[]` 动态生成，首项"全部"（不传参） |
| 【刷新】 | 点击 | `GET /summary` + `GET /items` 并发 | 完成后 Toast"已刷新"；按钮进入 loading 并禁用，防止重复点击 |
| 【+ 新增交付项】 | 点击 | 无 | 打开 A5，标题"新增交付项"，表单清空，进度默认 0 |

### A3 数据表格

列：阶段名称（`phaseName` + 下方小字 `id`）、负责人（`owner`）、计划开始（`plannedStart`）、计划完成（`plannedEnd`）、实际完成（`actualEnd`）、当前进度（`progressPercent` 进度条 + 百分比）、状态（`statusLabel` + 人工覆盖时"人工"角标）、操作。

- **可操作**：行内【编辑】打开 A5 并回填；行内【删除】先 `confirm("确认删除交付项「<phaseName>」？")`，确认后 `DELETE /api/delivery/items/{id}`，成功 Toast 并刷新。
- **纯展示**：表头、单元格文本、进度条、状态标签、`manual` 角标。点击单元格无任何响应。
- **排序**：服务端已按 `plannedEnd` 升序、null 最后；前端不再排序。
- **行数**：不分页，展示接口返回的全量。

### A4 空态区（纯展示）

筛选结果为空时显示"当前筛选条件下没有交付项"，并保留表头；不显示"暂无数据"再叠加 Toast。

### A5 新增/编辑弹窗

标题：新增时"新增交付项"，编辑时"编辑交付项 · `<id>`"（纯展示）。

| 字段 | 控件 | 必填 | 校验（前端，服务端仍为准） |
|---|---|---|---|
| `phaseName` | 文本 | 是 | 非空白，否则 Toast"请填写交付阶段名称" |
| `owner` | 文本 | 是 | 非空白 |
| `plannedStart` | `datetime-local step=1` | 是 | 必填 |
| `plannedEnd` | `datetime-local step=1` | 是 | 不早于 `plannedStart` |
| `actualEnd` | `datetime-local step=1` | 否 | 填了即视为完成（服务端推导） |
| `progressPercent` | number 0–100 | 否 | 越界时 Toast |
| `status` | 下拉 | 否 | 选项：自动推导（空）/ 四状态 / 编辑时若存在 `statusOverride` 追加"恢复自动推导（AUTO）" |

- **可操作**：输入、下拉、`datetime-local` 选择器、【保存】、【取消】、点遮罩关闭、Esc 关闭。
- **纯展示**：标题、必填星号、字段下方 hint 文案。
- **提交**：新增 `POST /api/delivery/items`（期望 201）；编辑 `PUT /api/delivery/items/{id}`（期望 200，部分更新：未填字段传 null 保持原值）。
- **提交中**：保存按钮 disabled + "保存中…"，防重复提交。
- **返回处理**：
  - 2xx → 关闭弹窗、Toast"已新增/已更新"、刷新汇总与列表；
  - 400 `VALIDATION_FAILED` → Toast `message`，标记 `field` 对应输入框，弹窗保持打开；
  - 404 `NOT_FOUND` → Toast，刷新列表；
  - 202 `PENDING_APPROVAL` → 关闭弹窗、Toast 黄色"已提交审批：`approvalTicketId`"，刷新列表（此时数据未变）；
  - 403 → Toast 拒绝码与原因，弹窗保持打开。

### A6 列表底部说明（纯展示）

"共 N 条，按计划完成时间升序排列。状态由计划时间与进度自动推导，逾期即刻显示为「已延期」。" N 取当前列表长度。

### A7 Toast（纯展示）

右下角堆叠，3.2 秒自动淡出；`ok` / `warn` / `err` 三种左边框色。不拦截点击。

## 4. 页签 B：治理管理

> 统一信封 `{code,message,data,error}`：`code==0` 且 HTTP 200 视为成功；失败按 `error` 分支。
> 所有请求带 `X-Governance-Token: <G4 保存的令牌>`。
> 单条失败不整页报错，只在对应区域显示错误横幅（G3）。

### B0 令牌与授权态

| 状态 | 表现 |
|---|---|
| 未配置令牌 | 区域遮罩文案"未配置治理令牌" + 【去配置】按钮（打开 G4）；所有操作 `disabled` |
| 已配置但 401 `UNAUTHORIZED` | 横幅"令牌无效或已过期" + 【重新配置】；保留已加载的只读数据 |
| 403 `ADMIN_API_DISABLED` | 横幅"管理接口未配置访问令牌（服务端 metrics-token 为空）"；操作禁用 |
| 404（响应体不是统一信封） | 横幅"管理接口未开启（towndemontower.admin-api-enabled=false）"；操作禁用 |

上述四种状态均**不重试**，避免令牌错误时刷请求。

### B1 审批单区（4 个操作）

子导航：`审批单` / `计划单` / `审计` / `同步暂存`（可操作，纯前端切换，零请求）。

| # | 控件 | 操作 | 请求 | 成功返回处理 |
|---|---|---|---|---|
| B1-1 | 状态下拉 | 选择 | `GET /towndemontower/admin/approvals?status=` | 重绘表格；`total` 写入底部计数 |
| B1-2 | 【刷新】 | 点击 | 同上（沿用当前筛选） | 重绘 |
| B1-3 | 行内【详情】/ 点击行 | 点击 | 无请求 | 打开右侧抽屉，只读展示 13 字段 |
| B1-4 | 【批准】/【驳回】 | 打开弹窗 → 填 `approver`/`comment` → 提交 | `POST /approvals/{id}/approve` 或 `/deny` | 关闭弹窗、Toast、刷新列表 |

**列表列**：id、taskId、tool、riskLevel、requestedBy、status、createdAt、deadline、approver、操作。
**排序**：服务端按创建时间倒序（最新在前），前端不再排序；**无分页**。

**详情抽屉字段（纯展示，13 个）**

| 字段 | 类型 | 格式 | 业务含义 |
|---|---|---|---|
| `id` | string | `T<毫秒>-<序号>` | 审批单号 |
| `taskId` | string | 文本 | 触发拦截的任务号 |
| `tool` | string | 工具名 | 被拦截的工具 |
| `riskLevel` | string | `R2`/`R3` 等 | 风险等级 |
| `impactNote` | string | 文本 | 影响说明 |
| `rollbackPlan` | string | 文本 | 回滚方案 |
| `requestedBy` | string | agentId | 申请人（禁自批对象） |
| `status` | string | `PENDING/APPROVED/DENIED/EXPIRED` | 单据状态 |
| `createdAt` | string | ISO Instant（UTC） | 创建时刻 |
| `deadline` | string | ISO Instant（UTC） | 审批截止时刻 |
| `approver` | string \| null | 文本 | 审批人 |
| `comment` | string \| null | 文本 | 审批意见 |
| `decidedAt` | string \| null | ISO Instant | 决策时刻 |

**批准/驳回弹窗**

| 字段 | 必填 | 规则 |
|---|---|---|
| `approver` | 是 | 为空时前端提示"审批人不能为空"；等于 `requestedBy` 时提示"不能自批"（服务端仍会二次校验） |
| `comment` | 否 | 自由文本 |

- **按钮禁用规则（纯展示态）**：`status != PENDING` 时【批准】【驳回】`disabled`，悬停提示"该单已 <status>，不能再次决策"。
- **返回处理**：200 → 更新抽屉与列表；400 `SELF_APPROVAL`/`VALIDATION_FAILED` → 弹窗内红字；404 → Toast + 刷新；409 `NOT_PENDING`/`CONFLICT` → Toast 带服务端当前状态 + 刷新列表（**不自动重试**）。

### B2 计划单区（4 个操作）

| # | 控件 | 操作 | 请求 |
|---|---|---|---|
| B2-1 | 状态下拉 + `agentId` 输入 + `taskId` 输入 | 点【查询】/ 回车 | `GET /towndemontower/admin/plans?status=&agentId=&taskId=` |
| B2-2 | 【重置】 | 点击 | 清空三条件并重新查询 |
| B2-3 | 行内【详情】/ 点击行 | 点击 | 无请求（数据来自列表项） |
| B2-4 | 【批准】/【否决】 | 弹窗填 `approver`/`note` → 提交 | `POST /plans/{id}/approve` 或 `/reject` |

**列表列**：id、agentId、taskId、status、summary、requestedAt、decidedAt、decidedBy、操作。
**排序**：服务端按提交时间升序；无分页。

**详情抽屉字段（13 个）**

| 字段 | 类型 | 格式 | 业务含义 |
|---|---|---|---|
| `id` | string | `P<毫秒>-<序号>` | 计划单号 |
| `agentId` | string | 文本 | 提交计划的 agent |
| `taskId` | string | 文本 | 计划所属任务号 |
| `status` | string | `PENDING/APPROVED/REJECTED` | 计划状态 |
| `summary` | string | 文本 | 计划摘要 |
| `requestedAt` | string | ISO Instant | 提交时刻 |
| `decidedAt` | string \| null | ISO Instant | 决策时刻 |
| `decidedBy` | string \| null | 文本 | 决策人 |
| `note` | string \| null | 文本 | 审批备注 |
| `plan.summary` | string | 文本 | 结构化计划摘要 |
| `plan.steps` | array | `[{tool,intent}]` | 步骤序列（有序，展示为编号列表，**只读**） |
| `plan.steps[].tool` | string | 工具名 | 该步工具 |
| `plan.steps[].intent` | string | 文本 | 该步意图 |

- 已批准时【批准】保持可点（幂等），点击后 Toast"该计划已是批准状态"，不视为错误。
- `status==REJECTED` 时【批准】`disabled`，提示"已否决，不能补批"（服务端 409 `PLAN_REJECTED` 为兜底）。
- `approver` 为空或等于 `agentId` → 与服务端一致的 400/400 提示。

### B3 审计区（2 个操作 + 分页）

| # | 控件 | 操作 | 请求 |
|---|---|---|---|
| B3-1 | `action` 输入、`q` 输入、`limit`(1–500)、`offset`(≥0) | 点【查询】/ 回车 | `GET /towndemontower/admin/audit?action=&q=&limit=&offset=` |
| B3-2 | 【上一页】 | 点击 | 同接口，`offset = max(0, offset-limit)` |
| B3-3 | 【下一页】 | 点击 | 同接口，`offset = offset+limit`；`offset+limit >= total` 时禁用 |
| B3-4 | 【重置】 | 点击 | 清空条件，`limit=100, offset=0` 重新查询 |
| B3-5 | 【校验链】 | 点击 | `GET /towndemontower/admin/audit/verify` |

**列表列**：seq、action、hash（等宽字体，可首尾截断展示，悬停显示全文）、payload。

**字段**

| 字段 | 类型 | 格式 | 含义 |
|---|---|---|---|
| `total` | int | ≥0 | 命中总数（用于分页判断） |
| `limit` | int | 1–500 | 生效页大小（回显到输入框） |
| `offset` | int | ≥0 | 生效偏移 |
| `items[].seq` | long | ≥1 | 链内序号，升序 |
| `items[].action` | string | 大写下划线 | 动作名 |
| `items[].hash` | string | 64 位小写十六进制 | 链摘要（HMAC-SHA256；无密钥时 SHA-256） |
| `items[].payload` | string | 原始文本 | 动作内容；`q` 为其子串匹配 |

- **payload 展开/折叠**：纯展示，本地切换 CSS，**不发请求**。
- 空结果：表格显示"无匹配记录"，`total=0`。

**校验链结果面板（纯展示 + 结果来自 B3-5）**

| 字段 | 类型 | 展示规则 |
|---|---|---|
| `valid` | boolean | 绿色"链完整" / 红色"链校验失败" |
| `records` | int | "共 N 条" |
| `anchorRecords` | int | 仅文件存储返回；缺失显示 `—` |
| `anchorLag` | int | 同上；>0 时提示"锚点追平中，属正常" |
| `replicaFailures` | int | 同上；>0 时标红 |

### B4 同步暂存区（4 个操作）

| # | 控件 | 操作 | 请求 | 返回处理 |
|---|---|---|---|---|
| B4-1 | 【刷新概览】 | 点击 | `GET /sync-spool`（不传 limit，取默认 50） | 重绘统计卡与待补传表 |
| B4-2 | 【查看死信】 | 点击 | `GET /sync-spool/dead`（不传 limit，取默认 50） | 切到死信表视图，显示 `deadTotal` |
| B4-3 | 【立即补传】 | 点击（需二次确认） | `POST /sync-spool/retry` | Toast"送达 d / 重试 r / 死信 x / 跳过 s"，随后刷新概览与死信 |
| B4-4 | 【立即清理】 | 点击（需二次确认） | `POST /sync-spool/cleanup` | Toast"按时间删 a / 按容量删 b / 剩余 n（字节 B）"，随后刷新 |

**统计卡（纯展示，8 张）**：`pending`、`pendingBytes`、`dead`、`deadBytes`、`captured`、`delivered`、`failed`、`deadLettered`。字节数格式化为 B/KB/MB（一位小数）。

**概览字段**

| 字段 | 类型 | 格式 | 含义 |
|---|---|---|---|
| `dir` | string | 绝对路径 | 暂存目录（只展示，不提供打开/跳转） |
| `stats` | object | 11 项 | 累计计数，见下 |
| `pendingTotal` | int | ≥0 | 待补传总数（非当前页） |
| `items` | array | 6 字段 | 当前页待补传 |

`stats` 11 项：`pending`、`pendingBytes`、`dead`、`deadBytes`、`captured`、`retried`、`delivered`、`failed`、`deadLettered`、`dropped`、`skipped`（含义见 docs/33 §6）。

**记录表（6 列，纯展示 + 折叠展开）**

| 字段 | 类型 | 格式 | 含义 |
|---|---|---|---|
| `file` | string | `spool-<毫秒>-<序号>.rec` | 暂存文件名 |
| `replica` | string | 副本名 | 目标锚点副本 |
| `attempts` | int | ≥0 | 已尝试次数 |
| `createdAt` | string | ISO Instant | 落盘时刻 |
| `lastError` | string | 文本 | 最近失败原因（空显示 `—`） |
| `snapshot` | string | 单行 JSON | 锚点快照原文；默认折叠，点击展开为格式化 JSON（本地解析，失败则原样显示） |

- 404 `SPOOL_DISABLED` → 区域整体切换为禁用态：文案"同步暂存区未启用（需文件审计存储 + 至少一个锚点副本）"，四个按钮全部 `disabled`，**不重试**。
- 400 `INVALID_PARAMETER`（limit 越界）→ 对应字段红框 + 提示。

## 5. 交互规则汇总

### 5.1 通用

| 规则 | 说明 |
|---|---|
| 加载态 | 发起请求的按钮进入 `disabled` + 文案"处理中…"，直到响应返回；同一区域同时只允许一个在途请求 |
| 重复点击 | 在途期间忽略点击 |
| 错误 | 按 `error` 码分支，不按 `message` 文本匹配 |
| 成功判定 | 统一信封：`code==0`；交付看板非信封接口：HTTP 2xx 且非 202 |
| 202 | 交付看板写操作的"已提交审批"，按警告处理：不当作失败、不刷新为成功态 |
| 409 | 状态冲突：Toast 显示服务端 message（含当前状态），刷新对应列表，**不自动重试** |
| 时间格式 | 交付看板为 LocalDateTime（无时区）；治理后台为 ISO Instant（UTC，带 `Z`）；页面统一按浏览器本地时区显示，悬停显示原始值 |
| 空值 | 一律显示 `—` |
| 键盘 | Esc 关闭任意弹层；弹层内 Tab 循环，焦点回到触发按钮 |
| 无障碍 | 可操作元素为原生 `button`/`input`/`select`；纯展示区域不加 `role=button`、不加 `cursor:pointer` |

### 5.2 禁止项（实现时不得出现）

1. 纯展示区挂 `onclick` 或 `fetch`。
2. 乐观更新（先改 UI 再等响应）——治理决策必须以服务端结果为准。
3. 自动轮询管理接口（令牌错误会放大失败请求）。
4. 把令牌写入 `localStorage`、URL、DOM 文本或日志。
5. 前端自行推导交付项状态（必须用服务端 `status`/`statusLabel`）。

## 7. 错误处理与状态映射

| 场景 | 界面表现 |
|---|---|
| 交付看板 400 `VALIDATION_FAILED` | 弹窗保持打开，`field` 对应输入框红框，Toast message |
| 交付看板 404 `NOT_FOUND` | Toast，关闭弹窗，刷新列表 |
| 交付看板 202 `PENDING_APPROVAL` | 警告 Toast（含 `approvalTicketId`），关闭弹窗，列表保持原值 |
| 交付看板 403 | Toast：`error` + message（如 `PERMISSION_DENIED`/`R3_DENIED`） |
| 认证 401 `CALLER_UNAUTHENTICATED` / `AUTH_TOKEN_UNAVAILABLE`、403 `CALLER_NOT_LOCAL` | 全局横幅：前者提示"Bearer 令牌缺失或不匹配"；后者提示"写操作仅允许本机，或改用 token 模式" |
| 治理 401 `UNAUTHORIZED` | B 页签横幅 + 打开 G4 |
| 治理 403 `ADMIN_API_DISABLED` | B 页签横幅："服务端未配置 metrics-token" |
| 治理 404 `SPOOL_DISABLED` | 仅 B4 区域禁用 |
| 治理 404 非信封 | B 页签横幅："管理接口未开启" |
| 治理 400 `INVALID_PARAMETER`/`INVALID_STATUS` | 对应控件红框 + 提示 |
| 治理 400 `SELF_APPROVAL` | 弹窗内红字 |
| 治理 409 `NOT_PENDING`/`CONFLICT`/`PLAN_REJECTED` | Toast + 刷新当前列表 |
| 治理 500 `INTERNAL_ERROR` | 区域横幅"服务内部错误，请查看服务端日志"（不回显堆栈） |
| 网络失败/超时 | 区域错误横幅 + 【重试】；不自动重试 |

## 8. 刻意不提供的界面操作

| 不存在 | 原因 |
|---|---|
| 新建审批单 / 新建计划单 / 提交计划 | 只能由治理链或 agent 在运行时生成，界面建单等于绕过闸门 |
| 删除审批单 / 计划单 | 决策结果只覆盖状态，单号永久保留 |
| 删除待补传记录 / 编辑快照 | 暂存区是"未送达的证据"，可删即可抹除同步失败 |
| 修改审计记录 / 补写审计 | 审计链只追加 |
| 切换运行模式 / 授予权限 / 放行 R3 | 治理决策不走管理接口 |
| 导出令牌 / 复制令牌到剪贴板 | 降低泄露面 |
| 页面内时间范围筛选（审计） | 后端无时间字段，只有 seq/action/hash/payload |

## 9. 数据口径（避免展示歧义）

- **状态推导**（服务端）：人工覆盖 > 进度 100% 或 `actualEnd` 非空 → 已完成 > 超 `plannedEnd` → 已延期 > 有进度或已到 `plannedStart` → 进行中 > 未开始。
- **整体进度**：各项进度之和 ÷ 总数，向下取整；**完成率**：已完成 ÷ 总数，向下取整。
- **“下一个交付节点”**：未完成且尚未到期项中最早的计划完成时间（已延期项不参与）。
- **审计 `total`**：过滤后的匹配总数；`items` 为 `offset..offset+limit` 切片。
- **审批/计划列表无分页**：`items` 即全量，`total == items.length`。
