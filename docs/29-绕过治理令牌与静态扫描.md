# v1.11 绕过治理令牌与静态扫描（D2 / CP-1 + CP-10）

> 本文是 v1.11 的交付记录，按 PM → Arch → Dev → QA → Ops 五段写。
> 前置阅读：`docs/17-强制力与绕过面分析.md`（绕过面清单）、`docs/18-防绕过方案.md`（防线设计）。
>
> 一句话：把"经过治理链"从**约定**变成**前置条件**（运行时令牌），把"绕过注解直调"从**无痕**
> 变成**构建期失败**（静态扫描）。这是 `docs/17/18/19/28` 四篇共同点名的头号缺口。

---

## 1. PM：要解决什么

### 1.1 问题

治理点是注解，而注解只在"从代理对象进来"时生效。两条最常见的失效路径因此完全无声：

| 编号 | 路径 | 治理链 | 审计 | 以前的表现 |
|---|---|---|---|---|
| BS-01 | 同类内部 `this.other()` 自调用 | 跳过 | 无 | 方法照常执行，看起来一切正常 |
| BS-03 | 别的类直接 `new`/注入下层 Service 调用 | 跳过 | 无 | 同上，且日志里查不到 |

`docs/28` 的专项核查把这条记为 **S-03 / G-1「当前最大结构性缺口」**。

### 1.2 目标

1. **运行时**：受治理方法在没经过链时**执行不了**，且失败必须留痕、可计数（`ungoverned_invocations_total` 正常恒为 0）。
2. **提交时**：注解用错位置、方法体里偷偷做副作用、首行忘了申请令牌、Controller 直调 Service——在**合入前**就被指出来，而不是等复盘时才发现。

### 1.3 明确不做

- 不做内核级强制（仍是框架层/进程内）；能改 jar、能 attach 调试器的人依然能绕。
- **不新增任何依赖**，不引入 ArchUnit / JavaParser / sonar-plugin-api（离线 `mvn -o` 是硬约束）。
- **不改 CI 配置**：只提供可执行的判据，接哪条流水线由接入方决定。

## 2. Arch：两条防线怎么设计

### 2.1 令牌生命周期

```
AOP 切面 → 装饰器链（10 层，顺序不变）→ 链尾 SandboxedToolExecutor
                                            │ issue(tool)          ← 唯一发牌点
                                            ├→ invoker.invoke → 方法体首行 require(tool) → 命中即弹出
                                            └→ finally clear(tool)  ← 兜底收牌
```

四条不变量：

1. **只在实际执行前发牌**：R2 待审批、R3 拒绝、取消、任一环拒绝都到不了链尾，自然不会发牌。
2. **一次性**：`require` 必须命中**栈顶**且工具名一致，命中即弹出；重复消费、串名、栈空都算违规。
3. **必须兜底清理**：`finally clear`。`delivery` / `agents` 的 facade 复用同一条链但目标方法没有 `require`，
   不清理的话残留令牌会让**同线程的下一次调用**误通过——这是本设计最危险的失效模式，已用"违规后仍可正常调用"的用例钉住。
4. **线程隔离**：令牌装在 ThreadLocal 栈里，换线程即失效。跨线程违规无法归属到某条链，因此**不计入**该链指标（宁可少记，不把别人的账记到自己头上）。

### 2.2 发牌口的收权（对 docs/18 草案的修正）

草案把 `issue()` 设成 public，等于"谁都能先自己发一张再直调方法"。实际实现把 `GovernancePass`
放在 `com.towndemontower.core.decorator` 包，`issue/clear` **包内可见**，只有同包的链尾能发。
这是**编译期**约束（同包与反射仍能破），与 CP-10 规则 R3 形成"发牌—验牌"闭环。

### 2.3 显式弃权作用域

`enabled=false` + `disabled-behavior=allow`（或过渡宽限）时没有链、没有发牌点，方法首行的 `require`
本不该因此失败。用一个**带痕的弃权作用域**兜住：

- 每开一次写一条 `GOVERNANCE_BYPASS_ISSUED` 审计 + 计一次 `explicitBypass`；
- **不**压低 `UNGOVERNED_INVOCATION`——两者分开计数，否则分不清"运维关的"还是"有人绕的"；
- 嵌套安全，内层关闭不撤销外层。

### 2.4 静态扫描：三段式而不是正则

直接对源码跑正则会被三类噪声毁掉：注释里的 `@AgentSkill`、字符串里的 `ProcessBuilder`、
需要按花括号配对才能确定的方法体。因此：

1. **词法净化**（`JavaSourceLexer`，单趟 O(n)，无回溯）：产出三份**等长**文本
   —— `clean`（注释+字面量抹平，用于结构定位）、`masked`（仅注释抹平，用于取实参）、
   `comments`（仅字面量抹平，用于识别豁免注释）。
2. **结构定位**（`BypassScanner`）：`@AgentSkill` → 参数区 → 跳过后继注解 → 形参括号 → 方法体花括号配对 → 首语句提取。
3. **规则判定**：

| 规则 | 检查 | 级别 | 挡住 |
|---|---|---|---|
| `CP10-R1` | `@AgentSkill` 必须在 `public`、非 `static/final/private/abstract` 方法上 | BLOCKER | BS-02 |
| `CP10-R2` | 方法体禁 `ProcessBuilder` / `Runtime.getRuntime` / `Files.write` / `new FileOutputStream` / `HttpClient` / `DriverManager` | BLOCKER | BS-04 |
| `CP10-R3` | 首条语句必须是 `GovernancePass.require("工具名")`，且与注解 `name` 一致 | BLOCKER | BS-01/03 |
| `CP10-R4` | Controller 不得直接注入 `*Service` | WARN（`--strict` 下阻断） | BS-03 |
| `CP10-META` | 豁免注释必须写明规则号与**非空理由** | BLOCKER | 万能豁免 |

`R4` 只报不拦的理由：`DeliveryController` / `AgentController` 构造器注入 Service 是当前被认可的写法，
一刀切阻断会让历史代码立刻红灯，违背 `docs/18 §9`"先有豁免流程再上扫描"的原则。

### 3.3 三个非显然的实现细节

1. **上报端随令牌帧走**。同进程内并存多条链（starter 主链、delivery、agents、测试），
   全局单例会让"违规记到谁的账上"取决于装配顺序。
2. **`LAST` 帧**：最常见的两种绕过（直调下层 Service、同一令牌重复消费）恰好发生在**栈已空**时。
   只按栈顶归属会"抛了异常但没计数"，而 `UNGOVERNED_INVOCATION` 恒为 0 正是"有没有人绕过"的唯一凭据。
3. **豁免必须是注释行首的指令**。文档里提到这个指令名很常见（本框架自己的 Javadoc 就提到），
   不加这个约束会把说明文字判成"缺理由的豁免"。

## 5. Ops：怎么用

### 5.1 运行时

无需额外配置。**默认就是 deny**：方法首行拿不到令牌即抛 `UNGOVERNED_INVOCATION`，
`GovernanceMetrics` 计数 +1，审计写一条 `UNGOVERNED_INVOCATION`（含工具名、原因、线程名）。

需要放行整段治理时，用**显式**配置而不是删掉 `require` 行：

```yaml
towndemontower:
  enabled: false
  disabled-behavior: allow   # 启动自检记 CRITICAL: DISABLED_ALLOW
```

此时每次调用额外留一条 `GOVERNANCE_BYPASS_ISSUED`，`explicitBypass` 计数增长。

### 5.2 构建期

```bash
# 本地/pre-commit/任何 CI 都能调；有违规即非 0
java -cp <core 类目录> com.towndemontower.core.bypass.BypassScanMain --root . 
```

接 SonarQube（零插件、零版本绑定）：把 `--report` 产出的 JSON 挂到扫描参数即可
`sonar.externalIssuesReportPaths=target/towndemontower-bypass.json`。

### 5.3 豁免

```java
// towndemontower:allow CP10-R2 reason=该工具就是沙箱执行器，构造进程是它的职责
@AgentSkill(name = "exec", risk = "R1")
public String exec(String cmd) {
    GovernancePass.require("exec");
    ...
}
```

规则：必须**注释行首**、必须写明规则号与**非空理由**。缺理由或规则号不存在 → `CP10-META` 违规，
原违规**照旧成立**（豁免无效）。扫描结束会逐条打印全部豁免，不允许静默跳过。

## 6. 边界与残留风险

1. **编译期收权不等于运行时收权**：`issue/clear` 包内可见，但同包代码、反射仍能发牌。真正的边界仍是进程隔离。
2. **扫描器只认字面量**：拼接的注解名、常量里的工具名、跨文件别名都会漏。
   它挡的是"手滑与顺手"，不是"处心积虑"——后者只能靠 code review 与变异测试。
3. **R4 不可豁免**（有意）：唯一一条"直调提示"如果能被静音，它就等于不存在；它只报 WARN，不阻断。
4. **跨线程违规不计入链指标**（见 §2.1 第 4 条）。若要观测这类调用，需要把调用者身份显式传递后再统计。
5. **令牌不跨异步**：`CompletableFuture`/线程池里调用受治理方法会直接失败——这是设计意图（令牌代表"这条调用栈正在被治理"），
   但接入方需要知道：异步执行必须从治理入口重新进入。
6. **仍不设防**：能改 jar / attach 调试器的人、方法体内部的任意 Java 能力、有 docker 组权限的用户（同 `docs/18 §10`）。
