# v1.12 命令模板化（I5）

> 本文是 v1.12 的交付记录，按 PM → Arch → Dev → QA → Ops 五段写。
> 前置阅读：`docs/18-防绕过方案.md §I5`（缺口定义）、`docs/29-绕过治理令牌与静态扫描.md`（v1.11 令牌与扫描）。
>
> 一句话：把"这条 shell 命令危不危险"这个**不可判定**的问题，换成"这条命令是否符合工具声明的形状"这个**可判定**的问题。

---

## 1. PM：要解决什么

### 1.1 原有做法的问题

v1.11 之前，shell 类工具的风险判定是这么走的：

```
意图参数里有 command → SimpleShellAstAnalyzer 正则黑名单 → 命中 rm -rf/kubectl delete/drop table 就升 R3
```

这条路有三个结构性毛病：

| 毛病 | 具体表现 |
|---|---|
| **列不完** | `find . -delete`、`base64 -d \| sh`、`xargs rm`、`${IFS}` 拼接……黑名单永远慢一步 |
| **误报逼人放宽** | 一旦业务里有正常命令被判 R3，运维就会把规则改松，最后回到"基本不拦" |
| **判据不可读** | 拒绝理由是"疑似危险"，不是"违反了某条明确约定"，无法在评审里对齐 |

### 1.2 本期做法

让工具**自己声明**它允许的命令形状：

```java
@AgentSkill(name = "restartService", risk = "R1",
            requiredArgs = {"service", "command"},
            commandTemplate = "systemctl restart {service}")
```

声明之后：

- 字面量位置固定，参数只能落在 `{...}` 槽位；
- **不允许多余的词**——追加 `; rm -rf /`、`| sh`、`-c …` 一律拒绝；
- 参数值**不允许**含 shell 控制操作符，单值占位符还不允许以 `-` 开头（选项注入）；
- 不符即 `COMMAND_TEMPLATE_MISMATCH`，理由可读、可审计、可统计。

### 1.3 不做什么

- **不替代 R 分级与 AST**：模板管"形状"，AST 管"形状合法但内容危险"（见 §2.4）。
- **不解析 shell 语法**：不支持引号、转义、管道。带引号的命令会被判不符——这是有意的取舍。
- **不改接口约定**：`SkillDescriptor` 保留 7 参构造，未声明模板的工具行为与 v1.11 完全一致。

## 2. Arch：怎么设计

### 2.1 模板语法

| 写法 | 含义 |
|---|---|
| `systemctl restart {service}` | 字面量 `systemctl` `restart` + 单值占位符 |
| `journalctl -u {unit} --since {since}` | 参数只能落在声明的三个槽位 |
| `docker logs {container} {args*}` | `{name*}` = 尾部参数区，匹配 **一个或多个** 词（至少一个） |

规则：按空白切词、词级匹配；占位符名 `[A-Za-z_][A-Za-z0-9_]*`、不得重名、最多 16 个；
字面量不得含控制操作符（写了就是模板打错）。

### 2.2 三条硬规则（缺一条机制就形同虚设）

1. **不允许多余词**：命令必须被完整消费。这一步直接消灭了"往合法命令后面接一句"的整类攻击。
2. **参数值不含控制操作符**：`; | & $ ` < > ( ) { } ! ' " \` 与空白控制字符一律拒绝。
   - 单值占位符额外禁止以 `-` 开头（`rm {target}` 配 `target=-rf /` 的经典注入）；
   - `{name*}` 是显式声明的尾部参数区，允许 `-` 开头的选项，但控制操作符仍然禁止。
3. **不支持引号与转义**：命令必须是"空格分隔的裸词"序列。带引号的命令直接判不符。

### 2.3 为什么放在风险分级**之前**

```
RiskGateDecorator.execute
  ├─ ① 工具未注册 → INTENT_FORMAT_INVALID（原来是 NPE）
  ├─ ② 命令模板校验（I5）→ 不符即 COMMAND_TEMPLATE_MISMATCH
  ├─ ③ 风险分级（R0-R3 + AST）
  └─ ④ 审批 / 拒绝 / 放行
```

顺序不能反：形状不符时"它有多危险"根本问不出可靠答案；更糟的是把形状非法的 R2 命令送进审批流，
等于把判断推给人。先卡形状，再谈风险。

### 2.4 与 AST 的关系：互补，不是替代

模板能保证"命令长得对"，但不能保证"长得对的命令不带危险动作"。所以 AST 仍然保留：

- 工具声明 `{cmd*}`（宽模板）时，`rm -rf /` 形状合法 → 由 AST 升 R3 拦下（已用用例钉住）；
- 工具声明窄模板时，AST 基本不会命中，但它是**第二道**，不是被删掉的那一道。

### 3.1 匹配算法

逐词回溯（`walk(tokenIndex, cmdIndex)`）：

- 字面量：必须逐字相等；
- 单值占位符：取一个安全词，绑定后递归，失败则回退（不允许重名绑定）；
- `{name*}`：从**最短**开始尝试（短匹配更容易让后面的字面量对上），逐词加长，遇到不安全词立即停止；
- 全部 token 消费完时要求命令也被消费完 —— 这就是"不允许多余词"的落点。

复杂度：最坏 O(词数 × 占位符数)，无正则、无字符串拼接；解析结果按模板字符串缓存
（模板是代码里写死的，数量有限），匹配路径不走 `Pattern`。

### 3.2 边界处理（本期新增的"稳妥应对"）

| 输入 | 处理 |
|---|---|
| `command` 为 null / 空白 | 不匹配，理由"命令为空" |
| 命令 > 2048 字符 | 不匹配，理由"命令过长" |
| 单参数 > 256 字符 | 视为不安全，不匹配 |
| 占位符重复 / 名字非法 / 字面量含 `;` | 模板解析期抛 `IllegalArgumentException`，运行期转 `COMMAND_TEMPLATE_INVALID` 拒绝 |
| 工具未注册 | `INTENT_FORMAT_INVALID` 拒绝（原来是 NPE → 500） |
| `command` 不是字符串 | `commandOf` 返回 null → 按"命令为空"拒绝 |

### 3.3 顺手修掉的一个测试脆弱点

`BypassScanTest` 写样例文件时，连续跑多个 JVM 的场景下偶发 `AccessDeniedException`
（杀软/索引器短暂占用新建的 `.java`），表现为"退出码 1 但没有 RESULT"，排查成本很高。
现在写入带三次退避重试，准备阶段失败会打印明确原因并计入失败，不再产生"看不懂的退出码"。

## 5. Ops：怎么用

### 5.1 加一行注解

```java
@AgentSkill(name = "restartService", risk = "R1",
            requiredPerms = {"ops:restart"},
            requiredArgs = {"service", "command"},
            commandTemplate = "systemctl restart {service}")
public String restart(String service, String command) {
    GovernancePass.require("restartService");
    ...
}
```

`requiredArgs` 里别忘了 `command`——Schema 层先校验参数存在，模板层才有东西可校验。

### 5.2 写模板的建议

1. **先把固定词写全**：`systemctl restart {service}` 不要写成 `{cmd*}`；
2. **参数只放在"值"的位置**：选项（`-u`、`--tail`）写进模板，不要靠参数传；
3. **确实需要尾部参数区才用 `{name*}`**，并清楚它允许 `-` 开头的选项；
4. **模板写窄不会挡住合法调用**吗？会——所以先用一条真实命令试跑，再上量。

### 5.3 拒绝排查

| 错误码 | 含义 | 处理 |
|---|---|---|
| `COMMAND_TEMPLATE_MISMATCH` | 命令形状不符 | 看拒绝文案里的模板与实际命令，多半是多了参数或换了子命令 |
| `COMMAND_TEMPLATE_INVALID` | 模板本身写错 | 检查占位符名、重名、字面量里的 `;`、未闭合花括号 |

## 6. 残留风险

1. **模板覆盖不到"参数语义"**：`systemctl restart {service}` 里 `service` 传什么系统都会执行；
   模板保证不了目标是否合理（那是权限与业务校验的事）。
2. **`{name*}` 是显式放宽**：允许选项就意味着允许 `--force` 这类标志；要么别用尾部参数区，
   要么在业务层再校验具体选项。
3. **命令里不能有引号**：带空格的值必须走 `{name*}` 或改成"无空格的值"，
   这是能力边界，不是 bug。
4. **仍靠"工具作者写对"**：模板写得太宽（`{cmd*}`）等于没写。这一点由 code review 兜，
   扫描器目前没有"模板过宽"的规则（可作为 CP-10 的下一条规则）。
5. **预置工具名上的模板不会生效**：`SkillRegistry` 构造时已注册 `restartService` / `deployService` /
   `deleteData` / `writeFile` 等，切面的懒注册遇到"已存在"会跳过（这是 v1.1 起的既有行为）。
   要给这些名字加模板，必须显式 `registry.register(new SkillDescriptor(..., commandTemplate))` 覆盖；
   或者干脆用业务自己的工具名。**这一点在集成时最容易踩**，因为注解看上去"写了就该生效"。

## 7. v1.12.1 补强：CP10-R5「模板过宽」

### 7.1 为什么要补这一条

I5 的约束力全在"模板里有固定词"这件事上。如果模板写成 `{cmd*}`，它能匹配任意命令
——**声明了等于没声明**，而作者却会以为"我已经配了模板"。这是 I5 最容易被架空的方式，
必须在扫描器里点名。

### 7.2 判定与分级

| 项 | 规则 |
|---|---|
| 判定 | 按空白切词后，**没有任何一个词是字面量**（全部是 `{...}`） |
| 例 | `{cmd*}`、`{a} {b}` → 过宽；`systemctl restart {service}`、`docker logs {container} {args*}` → 不算 |
| 级别 | **WARN**（不是 BLOCKER）：确实存在"就是要透传"的工具，一刀切阻断会逼人删掉扫描 |
| 升级 | `--strict` 下与 R4 一样计为失败 |

### 7.3 与其他规则的一致性

- **豁免**：`// towndemontower:allow CP10-R5 reason=<非空>`，判定逻辑与 R1-R3 完全一致
  （`EXEMPT` 正则从 `R[123]` 扩到 `R[1235]`，缺理由仍记 `CP10-META`）；
- **Sonar 报告**：R5 与 R4 同属 `MAJOR`/`MEDIUM`（非 BLOCKER）；
- **输出位置**：与其他 WARN 一起打印，`--strict` 时进 `FAILED`。

### 7.4 实测

```
RESULT: files=231 violations=0 warnings=4 suppressions=0 -> PASSED
```

仓库内唯一的命令模板声明是 `V112TemplateWiringTest` 里的
`systemctl restart {service}`（有固定词），因此 R5 零误报。

用例新增 6 条（`BypassScanTest` 29 → 35）：纯通配告警、多占位符无字面量告警、
窄模板不告警、未声明不告警、过宽只提示不阻断、R5 可被显式豁免。
