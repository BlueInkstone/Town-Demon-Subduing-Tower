# 默认配置即安全（v1.6）

> 一句话：**不配置也不该降低安全性**。凡是"图省事"的开关，默认值一律取安全侧；
> 想放松必须显式写出来，并被自检记录、被审计留痕。

---

## 1. 实现范围

### 1.1 本期改动（core）

| 变更 | 文件 | 作用 |
|---|---|---|
| 新增可落盘审计 | `audit/FileAuditStore` | 继承 `HashChainAuditStore`，记录追加写文件、分段可追溯、启动时逐段校验；被篡改则拒绝启动 |
| 新增熔断执行器 | `executor/RejectAllExecutor` | 治理关闭时拒绝一切调用并留痕（`GOVERNANCE_DISABLED`） |
| 新增输入校验 | `executor/IntentArgsValidator` | 长度上限、控制字符、路径穿越、参数个数 |
| 错误信息脱敏 | `decorator/AuditDecorator` | `INTERNAL_ERROR` 不回显异常文本；业务提示压成单行限长 |
| 快照脱敏 | `executor/SnapshotService` | 支持注入脱敏器，清单与内存记录中的参数不再落明文 |
| 新增错误码 | `contract/ErrorCodes` | `GOVERNANCE_DISABLED` / `INPUT_REJECTED` |

### 1.2 本期改动（starter）

| 变更 | 文件 | 作用 |
|---|---|---|
| 默认值收紧 | `TownDemontowerProperties` | 见 §2 对照表 |
| 启动自检 | `GovernanceIntegrityChecker` | 落地显式授权；CRITICAL 项拒绝启动；自检结果写审计 |
| 授权入口 | 同上 | `permissions-bootstrap` 是默认配置下唯一的授予以外途径 |
| 输入校验接入 | `AgentSkillAspect` | 进链前校验，拒绝时直接写审计 + 计数（因为没经过审计装饰器） |
| 观测端点鉴权 | `GovernanceMetricsController` | 需 `X-Governance-Token`；未配置令牌一律 403 |
| 审计选择 | `TownDemontowerAutoConfiguration` | `audit-storage=file` 默认落盘；`memory` 被自检判 CRITICAL |
| 快照脱敏 | 同上 | `SnapshotService` 注入 `CredentialBroker::redact` |

### 1.3 明确不在本期范围

- 内核/OS 级隔离（seccomp、非 root 运行、egress 白名单）——见 `docs/17`、`docs/18`。
- REST 层身份认证（`towndemontower-agents` / `-delivery` 的接口仍无登录）。
- 审计 HMAC 与外锚（当前是明文 SHA-256 链，可检测改写但不可抗重算）。
- 工具方法体内副作用的拦截（`Runtime.exec` 等，需要 CI 静态扫描）。
- 治理引擎内部故障的专属强拦截异常（`GovernanceInternalException` / `GOVERNANCE_ENGINE_ERROR`）：本期只做到 `INTERNAL_ERROR` 拒绝 + 错误信息脱敏，异常不外抛。补充观点与取舍见 `docs/08`「未来发展方向」A-1。

## 2. 默认值对照表

| 配置项 | v1.5 默认 | v1.6 默认 | 安全含义 |
|---|---|---|---|
| `auto-grant-declared-perms` | `true` | **`false`** | 写注解不再等于自我授权；权限必须显式下发 |
| `enabled=false` 的语义 | 不装配切面（= 全放行） | **全拒绝**（`RejectAllExecutor`） | 关开关是熔断，不是拆闸门 |
| `disabled-behavior` | —（隐含 allow） | **`deny`** | 要放行必须显式写 `allow`，且被自检判 CRITICAL |
| `audit-storage` | —（内存） | **`file`**（`.towndemontower/audit.log`） | 审计重启不丢；启动校验断链 |
| `state-storage` | `memory` | **`file`**（`.towndemontower/state`） | 模式与裁决可追溯 |
| `approval-dir` | 空（内存） | **`.towndemontower/approvals`** | 审批单重启仍在 |
| `metrics-endpoint` | `false` | `false`（不变） | 不污染接入方 API 面 |
| `metrics-token` | 无 | **必填**（开端点时） | 遥测数据不裸奔 |
| `integrity-strict` | — | **`true`** | CRITICAL 配置直接拒绝启动 |
| `max-arg-length` / `max-args` | 无限制 | **1048576 / 64** | 给参数一个边界；上限不是"判断是不是正文"，定太小会误伤大文本写入 |
| `reject-control-chars` | — | **`true`** | 防日志伪造、终端注入 |
| `reject-path-traversal` | — | **`true`** | 防 `../` 越出工作目录 |

> **v1.9.2 补充**：`audit-anchor-batch` 默认 **`1`**（每写一条审计就把外锚追平一次），
> `audit-anchor-interval-ms` 默认 `0`。批量化是**显式性能选项**，不是默认值——
> 锚点落后期间被删掉的尾部记录无法被发现，这是证据强度换吞吐的交换，不能替接入方做决定。
> 详见 [25 · 审计写入收权与锚点追平](./25-审计写入收权与锚点追平.md)。

> **v1.10 补充**：`audit-anchor-replicas` 默认 **空**（只有本地锚点），
> `audit-anchor-replica-required` 默认 **`true`**。
> 默认留空是因为副本需要"第二块盘/第二台机"，框架无法替接入方假设这种部署形态；
> 但留空意味着**整目录回滚不可检出**，自检会报 `ANCHOR_SINGLE_COPY`(INFO) 持续提示。
> 一旦配了副本，`required` 默认就是 `true`——"配了但可以悄悄不生效"比"没配"更难发现。
> 详见 [26 · 锚点副本与回滚检出](./26-锚点副本与回滚检出.md)。

## 3. 四类措施与关键控制点

### 3.1 访问控制

| 控制点 | 实现 | 失败行为 |
|---|---|---|
| RBAC 默认拒绝 | 权限只能由 `permissions-bootstrap` 或注册表下发；`autoGrant` 默认关 | `PERMISSION_DENIED` + 审计 |
| 治理关闭 = 全拒 | `RejectAllExecutor`；切面保留，执行器替换 | `GOVERNANCE_DISABLED` + 审计 `GOVERNANCE_DISABLED_CALL` |
| 成员身份不被静默覆盖 | 模式来自 `GovernedModeSession`，配置改模式只留痕 | `MODE_OVERRIDE_IGNORED` |
| R2 批准权 | 非 `TrustedApprovalPolicy` 对 R2 的 `APPROVE` 改判转人工 | `PENDING_APPROVAL` + 审批单 |
| 审批禁自批 | 申请人与审批人相同（含都为 null）一律拒绝 | 决策失败，状态仍 PENDING |
| 观测端点 | `X-Governance-Token` 比对；未配置令牌 403 | 401 / 403 |
| 启动闸门 | `integrity-strict=true` 时 CRITICAL 拒绝启动 | 进程启动失败，原因含发现项编码 |

### 3.2 输入验证

进链前统一校验（`IntentArgsValidator`），不通过即拒绝，不进入任何工具：

- 单参数长度 > 1 MiB（1048576）→ 拒；
- 参数个数 > 64 → 拒；
- 含 NUL 或除 `\n \r \t` 外的控制字符 → 拒；
- 路径类参数（`path/file/target/source/dest/dir/...`）出现 `..` 段 → 拒。

拒绝结果：`INPUT_REJECTED`，写审计（因为未经过审计装饰器，由切面直接写），指标计数。

### 3.3 错误处理

| 场景 | 行为 |
|---|---|
| 内部异常 | 返回 `INTERNAL_ERROR` + 固定文案；异常文本只进审计，不进响应 |
| 业务提示 | 压成单行、限 200 字，避免多行伪造日志 |
| 治理拒绝 | 统一 `GovernanceDeniedException(code, message, ticketId)`，调用方可按 code 分支 |
| 审计写入失败 | 抛 `IllegalStateException`（不静默吞掉证据链断裂） |
| 状态落盘失败 | 不影响裁决，但写审计 `STATE_PERSIST_FAILED` |

### 3.4 数据保护

| 数据 | 措施 |
|---|---|
| 审计日志 | 追加写、分段（`#SEGMENT` + 前段尾哈希）、启动逐段校验、POSIX 下 `rw-------` |
| 审批单 | 每单独立文件，落盘后可跨重启查询；TTL 默认 1h，超时即拒 |
| 流水线状态 | 落盘可追溯；文件模式失败时降级内存并留痕 |
| 快照清单 | 参数与回滚提示经 `CredentialBroker` 脱敏，不落明文密钥 |
| 凭据 | 只在 `inject()` 瞬间还原明文，日志与审计只存哈希/占位符 |

## 4. 安全约束（硬 / 软）

**机制层不可通过配置绕过**（改了就是不安全，自检会拦）：

1. R3 默认拒绝；
2. R2 非受信策略不得自动批准；
3. 审批禁自批；
4. 装饰器链 10 个环节的顺序；
5. 治理关闭默认全拒；
6. 审计必须写入（含被拒调用）。

**可配置但会被记为发现项**（允许，但要留痕）：

| 配置 | 发现项编码 | 级别 |
|---|---|---|
| `enabled=false` + `allow` | `DISABLED_ALLOW` | CRITICAL |
| `audit-storage=memory` | `AUDIT_VOLATILE` | CRITICAL |
| `approval-dir` 为空 | `APPROVAL_NOT_PERSISTED` | CRITICAL |
| 开端点不配令牌 | `ENDPOINT_WITHOUT_TOKEN` | CRITICAL |
| `auto-grant-declared-perms=true` | `AUTO_GRANT_ENABLED` | WARN |
| 未配门禁密钥 | `GATE_DEV_KEY` | WARN |
| `agent-id` 为默认值 | `AGENT_ID_DEFAULT` | WARN |
| 输入校验被关闭 | `INPUT_VALIDATION_RELAXED` | WARN |

CRITICAL 在 `integrity-strict=true`（默认）下**拒绝启动**；WARN 只记录。

## 6. 兼容性影响与迁移

| 变化 | 受影响者 | 迁移动作 |
|---|---|---|
| `auto-grant` 默认关 | 依赖"注解即授权"的旧接入 | 配 `permissions-bootstrap`，或显式开 `auto-grant-declared-perms=true`（会告警） |
| `enabled=false` 变为全拒 | 曾用它"临时关掉治理"的环境 | 若要放行，显式配 `disabled-behavior=allow`（CRITICAL，需同时关 strict） |
| 审计/状态/审批默认落盘 | 只读文件系统的部署 | 显式改 `memory`（CRITICAL）或挂可写目录 |
| 端点需要令牌 | 已开 `metrics-endpoint` 的接入 | 配 `metrics-token`，请求带 `X-Governance-Token` |
| 输入校验默认开 | 传超长文本/相对穿越路径的工具 | 调整 `max-arg-length` 或显式关校验（会告警） |

## 7. 已知边界

1. 审计链仍无签名：能发现"被改写"，挡不住"整链重算"。密钥与外锚未做。
2. `PermissionEngine.grant` 仍是 public：进程内代码可自我授权；检测手段是对账与自检，不是阻止。
3. REST 无认证：`agents` / `delivery` 的 HTTP 面仍是"能访问即同权"。
4. 输入校验是通用卫生，不替代业务校验（如"目标路径必须在工作目录内"需工具自己判）。
5. 沙箱默认不装配：`SandboxedToolExecutor` 在 starter 主链里就是进程内调用；容器隔离需自行替换链尾。

## 8. 最小侵入边界：改动范围与影响

本节回答两个问题：**改了哪些地方**、**对既有功能有什么影响**。判定标准是"必要改动"——
凡是不影响安全目标、又能保持原结构或原行为的，一律保留原样。

### 8.1 改动分层

| 层次 | 内容 | 性质 |
|---|---|---|
| 新增类（6 个） | `FileAuditStore`、`RejectAllExecutor`、`IntentArgsValidator`、`GovernanceIntegrityChecker`、`GovernedModeSession`、`GovernanceMetricsController` | 纯新增，不改既有类 |
| 局部修改（core 4 处） | `SnapshotService`（真副本 + `restore()`）、`AuditDecorator`（错误脱敏）、`ErrorCodes`（+2 常量）、`ExecutorFactory`（+1 重载） | 只加方法 / 加分支，原方法签名不变 |
| 局部修改（starter 4 处） | `TownDemontowerProperties`（+配置项与新默认值）、`TownDemontowerAutoConfiguration`（新 Bean + 熔断分支）、`AgentSkillAspect`（进链前校验）、`GovernanceMetricsController`（令牌校验） | 装配层调整，不改 core 裁决逻辑 |
| **未触碰** | 装饰器链的 10 个环节与顺序、两个状态机转换表、`SkillDescriptor`/`ExecutionContext`/`SkillResult` 契约、模块边界、RBAC 判定逻辑 | —— |

### 8.2 刻意保留的兼容点

| 保留项 | 原因 |
|---|---|
| `ExecutorFactory.buildDefault` 8 参重载 | 旧调用方（含外部接入）不需要跟着改签名 |
| `AuditDecorator(next, audit)` 2 参构造 | 指标/状态为 null 时行为与改造前完全一致 |
| `RiskGateDecorator` 4 参构造 | 不传 `ApprovalCenter` 时退回旧语义 |
| `SnapshotService()` / `SnapshotService(Path)` | 旧构造仍可用；`snapshots`、`failNext` 字段语义未变 |
| `AgentSkillAspect` 6 参构造 | 本次补回：手工 `new` 本类的代码不受影响（此时不额外留痕、模式按配置解析） |
| `GovernanceMetricsController` 4 参构造 | 本次补回：不注入自检器时 `/integrity` 用降级计算 |

### 8.3 有意的行为变更（不可"零影响"，已逐条给规避方式）

| 变更 | 影响面 | 规避 / 回退 |
|---|---|---|
| `auto-grant-declared-perms` 默认 `false` | 依赖"写注解即授权"的接入首次调用会被 `PERMISSION_DENIED` | 配 `permissions-bootstrap`，或显式打开该项（自检告警） |
| `enabled=false` 变为全拒 | 用它"临时绕过治理"的环境会全部失败 | 显式 `disabled-behavior=allow`（CRITICAL，需关 strict） |
| 审计/状态/审批默认落盘 | 只读文件系统启动失败；工作目录多出 `.towndemontower/` | 改 `memory`（CRITICAL）或指定可写目录 |
| 输入校验默认开 | 传 `..` 相对路径、控制字符、超大参数的工具被拒 | 调整 `max-arg-length`，或关对应开关（告警） |
| `INTERNAL_ERROR` 文案固定 | 依赖异常文本做判断的调用方需改看 `code` | 完整信息仍在审计里 |

其中 `max-arg-length` 的默认值在落地后做过一次回调：**8 KiB 会误伤 `writeFile(path, content)` 这类合法大文本写入**，因此改为 1 MiB。
这是"安全默认值不得改变业务能不能跑"的一个具体例子——上限的作用是给边界，不是判断参数是不是正文。

### 8.4 对四个模块的影响

| 模块 | 影响 | 说明 |
|---|---|---|
| core | 无破坏性影响 | 仅新增类与重载；143 项测试（含 34 项原始回归）全绿 |
| starter | 两处默认值变更（见 8.3） | 旧构造器已补齐；71 项测试全绿 |
| delivery | 行为不变 | 走 starter 默认值，写操作仍经同一条链；219 项全绿 |
| agents | 行为不变（仅审计/状态落盘） | 权限闭环逻辑未改；201 项全绿 |

### 8.5 未做的"顺手改动"

- 没有为了放指标/状态而新增装饰器层（会让"链固定 10 层"失真）；
- 没有重写 `HashChainAuditStore`（新增 `FileAuditStore` 并存，可切换）；
- 没有改 `PermissionEngine.grant` 的可见性（属 API 收敛，需单独评估兼容性）；
- 没有给 `delivery` / `agents` 加页面或改路由（范围外）。
