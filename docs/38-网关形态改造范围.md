# 网关形态改造范围（2026-11-12 拍板，方案已落档待实现）

> 本文是「网关形态」改造的权威范围基线。实现时逐项勾销，禁止范围蔓延。
> 背景与触发：用户判定「多语言各写一套治理实现」过重，改为「一份 Java 裁决服务 + 一份 JSON 协议 + 一个 ≤200 行 Python 薄包」，其余语言只给 HTTP 示例，不维护 SDK。
> 产品名仍叫 **Town Demon-Subduing Tower（镇妖塔）**；「墨铠」仅作为网关服务名与客户端装饰器前缀 `@inkarmor_guard`，不是产品改名。
> 本文档只落范围与取舍结论；**代码实现（网关模块、Python 薄包、Dockerfile、测试）按后续授权另行开工**。

---

## 1. 目标

把产品从「每个语言各写一套治理实现」改成「**一份 Java 裁决服务 + 一份 JSON 协议**」：

- **服务端**：现有 Java 实现包成独立可运行的轻量 Web 服务 / Docker 镜像，暴露 `POST /api/evaluate`。
- **客户端**：Python 一个 ≤200 行薄包（`@inkarmor_guard`），只做打包 JSON、发 HTTP、按响应阻断；Go / Node 只给 `http.Post` / `axios.post` 示例。
- **验收口径**：任意语言照协议发一个 JSON，10 分钟内能拿到「允许 / 拒绝 / 待审批」；**不为任何语言维护 SDK**。

## 2. 范围边界

**做**：协议定稿、网关服务与镜像、`/api/evaluate`、Python 薄包与多语言示例、文档与排期改写、对应的测试与门禁。

**不做**（明确划界，避免范围蔓延）：不在 Python / Go / Node 里重写拦截链或审计链；不做管理端点建单；不做后台自动收紧（已否决，不复活）；不引入模型判定；不改造 `delivery` / `agents` 两个演示模块；不新增第二个回报接口（先接受「审计只记裁决」）。

**作废**：三份审计日志互验、跨语言结构比对用例、四个待评审错误码的语义结论（只剩一份 Java 实现，不再需要对齐）；两份 SDK 及其契约统一工作。

## 3. 已确认的设计决策（用户拍板）

| 项 | 决策 |
|---|---|
| ①「只裁决不执行」入口 | 在 core 新增**一条不含执行层的评估链装配**（复用前 9 层裁决，跳过 `SandboxedToolExecutor` 执行层），不采用「注入空 invoker 后调现链」（会误发 `GovernancePass` 令牌、误写快照/审计） |
| ② `ExecutionContext` 来源 | 由**服务端配置**提供 `agentId` / `mode` / `tainted`，请求只带 `IntentObject` 6 字段 + 可选覆盖字段，保证「10 分钟接入」成立 |
| ③ 命名 | 产品名不动（镇妖塔）；「墨铠」仅作网关服务名与 `@inkarmor_guard` 前缀 |
| ⑤ SDK 归档方式 | 保留目录、置为只读归档（不物理删除，保住历史可追溯） |

> 关键约束：现有 `Executor.execute()` 会走完整 10 层链并**真的执行**业务方法（链尾 `SandboxedToolExecutor` 调 `SkillInvoker`，starter 里靠 ThreadLocal 绑定 `pjp.proceed()`）。网关直接复用会抛「未绑定 per-call invoker」。因此 ① 必须落地，不能图省事复用现链。

## 5. 第④项取舍结论（旧排期三项在网关形态下）

核心前提：网关形态把强制力从「进程内强制」降级为「按约定前置询问」——**所有依赖「治理覆盖 100% 调用」的能力，有效性上限 = 调用方遵守协议的程度**。

| 原批次 | 网关形态下结论 | 作用域 / 语义调整 |
|---|---|---|
| 二 · 降权建议单 | **仍做**。证据源更单一干净（全在 Java 服务端）；实现更易（注册表在服务端，降权=服务端直接收紧拒绝，不用同步客户端）。作用域明确写成「**仅覆盖已接入网关的请求**」（与 `docs/16` 工程思想第 6 条「承认边界」自洽：嵌入式边界是 JVM 进程，网关边界是「是否调网关」） | M1 报告（已做）→ 人工批准 → 服务端注册表收紧 → 到期恢复；作用域写明「仅已接入网关的请求」 |
| 三 · 治理引擎可靠性 | **全保留，优先级上升**（服务可用性 = 治理可用性）。① 语义改写：从「抛异常中断业务方法」改为「裁决链内部异常一律转为明确拒绝响应 + 审计留痕 + 堆栈，绝不静默吞」。② 启动自检更重要。③ 健康检查是服务刚需（K8s 探针）。④「绝不静默失效」在网关形态下更站得住，前置条件仍是 ① 落地 | ① 改写后语义：裁决链内部异常 → 明确拒绝响应（非中断进程）。异常时整服务可全拒（非 5xx），偏好待定 |
| 四 · 上下文与数据安全 | **②③ 保留；① 降级**。「意图级快照」在网关里没有业务态可回滚（网关不执行），降级为「**请求级留证快照**」（intent + context + 裁决 + 响应），用于事后溯源，不做回滚；并与审计链区分清楚（审计链记裁决，快照记请求上下文） | ① 降级为「留证快照（无回滚）」；或初版网关干脆不做快照、只靠审计链留证（偏好待定）。② 提示词哨兵（确定性规则、默认关闭、命中留审计、误报可豁免）独立有效。③ 一键红队演练（隔离、禁真实数据源、不污染指标）独立服务更利于落地 |

## 8. 当前状态（2026-11-12 实测更新）

**已落地且本地实测通过**：

- 网关模块本体（改动 1–4、8）：无 Spring，JDK 内置 `HttpServer`；thin jar + `lib/` 分发包，字节码 class 52，在 JRE 8 上实跑
- `POST /api/evaluate` 全部分级行为：R0/R1 放行、R2 转审批、R3 拦截、模式白名单、非法意图、低置信、参数超长/控制字符
- 鉴权 fail-closed（缺/错令牌 401、未配令牌 403、非 POST 405、非法 JSON 400）
- 客户端侧（改动 9、10）：Python 薄包与 Go / Node / curl 示例；Python 单测 6/6
- 协议 golden（改动 19）：`contract/gateway-golden.json` 结构复算 69/69
- 文档改写（改动 14–18）：`docs/39-网关接入指南.md` 是本形态的接入与局限说明

**尚未完成（不得在文档里写成已具备）**：

| 项 | 现状 |
|---|---|
| R2 审批闭环 | 单号为进程内自增，无审批中心、无查询/批准端点，重启即丢。补这一项要新增端点，与 §2「不做管理端点建单」冲突，需先拍板 |
| 限流（改动 2、20） | 只有上限没有限流：线程池固定 8 且队列无界，并发打满后排队而非 429；请求体上限 4 MiB（413）挡的是单个超大 body |
| 请求超时 | 走 JDK `HttpServer` 内部开关，定时检查后断连接，属尽力而为、非 SLA |
| 镜像（改动 5、21） | Dockerfile 已按 thin jar + `lib/` 结构改写（原版会因缺 `lib/` 启动失败），**本机无 docker 守护进程，未实测** |

**本轮已补齐**：

| 项 | 现状 |
