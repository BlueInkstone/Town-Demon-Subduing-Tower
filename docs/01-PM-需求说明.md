## 1. 产品定位（一句话 + 边界）

Town Demon-Subduing Tower **不是一个独立程序**，而是一个**嵌入用户 Spring Boot 程序的治理 starter**：用户加依赖，程序跑起来时，Town Demon-Subduing Tower 在「工具调用边界」上做**拦截 → 分级 → 审批 → 审计**。

核心命题（D11–D22 收敛）：
- **模型只负责「想做什么」**（输出结构化意图对象），**闸门负责「能不能做」**（风险分级、审批、执行、回滚）。
- **状态机管「现在能不能做」**，**安全闸门管「这个动作本身是否被允许」**，二者 **AND**，再加 **第三层 AND：当前 AgentMode 工具白名单**。
- **core 纯 Java、不依赖 Spring**；契约语言中立（禁 Optional / CompletableFuture / Java 序列化，统一 JSON）；一切**可审计、可快照、可回滚、可急停**。

## 2. 本次构建目标（Scope）

按 README `0.5.4 落地顺序`与 `8.5 实施路线`，第一版交付 **Phase 0：core 骨架 + v1.3 新增契约接口**，跑通最小链路：

```
意图校验 → 模式白名单校验 → 风险分级(R0-R3) → 拒绝 / 放行
```

**纳入本次实现（core，纯 Java，零外部依赖）：**
1. `contract/`：IntentObject、Executor、SkillDescriptor、RiskLevel、ExecutionContext、错误码常量
2. `statemachine/`：TaskStatus 转换表 + Guard 接口 + TransitionResult
3. `policy/`：RiskGate 风险分级器（R0–R3、复合命令取最高、未知默认 R2、重定向不按只读、AST 解析失败降级 R2）
4. `decorator/`：Permission / Audit / Snapshot / RiskGate 装饰器组合（装饰器链：ModeToolPolicy → IntentFormat → Schema → Capability → RBAC → RiskGate(AST) → ApprovalRequired → TaintCheck → Snapshot → SandboxedTool → Audit）
5. `audit/`：哈希链接口 + 追加写接口（内存实现即可）
6. `mode/`：AgentMode 枚举、ModeToolPolicy、模式转换表
7. `context/`：ContextSelector 接口、PipelineState POJO、PipelineStateStore 接口（内存/YAML 实现）
8. `gate/`：GateScript 接口、GateResult、门禁重试策略
9. `approval/`：ApprovalPolicy 接口、ApprovalDecision、Guardian 预审接口（Guardian 只预审，不终批 R2 / 不批 R3）
10. `routing/`：ModelRouter 接口、ModelProfile
11. `executor/`：Executor 接口 + 最小链路 `execute(IntentObject)`，integration test 用 MockLlmProvider（零 token）

**明确不纳入本次（排后，按 README 10.6）：**
- towndemontower-spring-starter 的 `@AgentSkill` / AOP / AutoConfiguration / `@Transactional` / Outbox / WS（仅给出薄适配层接口约定，不实现）
- 凭据代理 CredentialBroker 运行时、容器级沙箱、War Room 面板、多模态预处理、多 Agent 编排引擎
- Python/JS SDK

## 3. 功能需求（FR）

| 编号 | 需求 | 来源 | 优先级 |
|------|------|------|--------|
| FR-1 | 模型输出必须解析为意图对象 JSON；出现「建议你执行 X」等建议文本 → 返回 INTENT_FORMAT_INVALID | 1.3、2.2 | P0 |
| FR-2 | 置信度 < 0.5 → 不执行，返回 NEED_MORE_INFO（非拒绝）；0.5–0.85 执行并标记审计；>0.85 直接放行 | 2.3、8.1 | P0 |
| FR-3 | 风险分级 R0 直接放行 / R1 轻确认 / R2 变更单+人工审批 / R3 默认拒绝（带 --force 也不放行） | 0.3、5.4 | P0 |
| FR-4 | 复合命令按 `; && ||` 拆分取最高风险；未知命令默认 R2；带 `> >> tee` 重定向不按只读放行 | 0.3、8.1 | P0 |
| FR-5 | 状态机与安全闸门 AND：处于执行态也不能执行 R3 | 3.1、5.7 | P0 |
| FR-6 | 模式白名单第三层 AND：即使状态/闸门允许，当前 AgentMode 不允许的工具不可调（错误码 MODE_TOOL_NOT_ALLOWED） | 2.5.2、5.7 | P0 |
| FR-7 | 模式切换只能由状态机事件触发（PLAN_APPROVED 强制 PLANNING→EXECUTION）；非法转换返回 MODE_TRANSITION_INVALID | 2.5.1 | P0 |
| FR-8 | 每次 Tool 调用必过装饰器链；工具返回值进 untrusted 数据区，会话置 TAINTED 后写/外发改额外校验 | 2.1、3.8 | P1 |
| FR-9 | 写操作前三样落盘：命令原文 + 目标快照 + 预期回滚动作；审计追加写 + SHA-256 哈希链 | 3.9、5.6 | P1 |
| FR-10 | 门禁脚本（compile/unit-test/lint/eslint/schema-check）失败回灌模型自动修正 ≤3，超限 escalate；脚本签名校验失败拒绝执行 | 3.12 | P1 |
| FR-11 | ApprovalPolicy 抽象：用户/IM/CLI、Guardian 预审、全部拒绝、转人工终端；R3 不进普通审批只给指引 | 3.4 | P1 |
| FR-12 | Audit 在任何拒绝/异常下仍记录（Permission 拒绝时 Audit 仍追加） | 0.5.4 | P0 |
| FR-13 | PipelineState 落盘与恢复（当前模式、子任务状态、门禁结果、PlanArtifact 引用） | 2.5.4 | P1 |

## 5. 风险分级映射（需求基线，作为 Arch/Dev 硬约束）

| 等级 | 定义 | 默认策略 |
|------|------|----------|
| R0 | 只读：kubectl get、systemctl status、读日志 | 直接放行 |
| R1 | 可逆写：restart、docker restart | 轻量确认 / 短 TTL |
| R2 | 高风险写：部署、扩缩容、防火墙 | 变更单 + 显式人工批准（ApprovalGateway） |
| R3 | 不可逆：rm -rf、kubectl delete、DROP | 默认拒绝（R3_DENIED），转人工终端 |

## 6. 验收标准（AC，作为 Ops 上线的「完成定义」）

**Phase 0 验收（必须全部满足，否则不得进入 Ops）：**
- AC-1：core 所有单元测试通过，**不启动 Spring**。
- AC-2：用纯 Java 调用 `Executor.execute(intent)` 跑通「意图校验 → 模式白名单 → 风险分级 → 拒绝/放行」最小链路。
- AC-3：ModeToolPolicy 证明模式白名单生效（PLANNING 看不到 writeFile；DEV 看不到重规划工具）。
- AC-4：PipelineStateStore 能落盘与恢复，恢复后模式/子任务/门禁结果一致。
- AC-5：非法模式转换被拒并留审计；Permission 拒绝时 Audit 仍记录。
- AC-6：R3 即使带 `--force` 也返回 R3_DENIED；未知命令默认 R2；重定向不按只读。
